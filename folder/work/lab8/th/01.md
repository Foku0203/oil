# โมดูล 11: Lab 8 – ระบบอัตโนมัติด้วย CloudFormation (Automation with CloudFormation)
การ deploy โครงสร้างพื้นฐานอย่างสม่ำเสมอและเชื่อถือได้นั้นยาก ต้องให้คนทำตามขั้นตอนที่บันทึกไว้โดยไม่ใช้ทางลัดที่ไม่ได้บันทึกไว้ นอกจากนี้ การ deploy นอกเวลาทำการเมื่อมีพนักงานน้อยก็อาจทำได้ยาก AWS CloudFormation เปลี่ยนสิ่งนี้ด้วยการกำหนดโครงสร้างพื้นฐานไว้ใน template ที่ deploy ได้อัตโนมัติ – แม้แต่ตามตารางเวลาอัตโนมัติ
แล็บนี้ให้ประสบการณ์ในการ deploy และแก้ไข CloudFormation stacks เป็นประสบการณ์แบบโต้ตอบ ที่คุณต้องค้นเอกสารเพื่อหาวิธีกำหนดทรัพยากรภายใน CloudFormation template
แล็บจะสาธิตวิธี:
- deploy AWS CloudFormation stack ที่กำหนด Virtual Private Cloud (VPC) และ Security Group
- ตั้งค่า AWS CloudFormation stack ด้วยทรัพยากร เช่น Amazon Simple Storage Solution (S3) bucket และ Amazon Elastic Compute Cloud (EC2)
- terminate AWS CloudFormation (stack) และทรัพยากรที่เกี่ยวข้อง

## งานที่ 3: เพิ่ม Amazon EC2 Instance ใน Stack
ในงานนี้ เป้าหมายของคุณคือเพิ่ม Amazon EC2 instance ลงใน template แล้วอัปเดต stack ด้วย template ที่แก้ไขแล้ว
ขณะที่การกำหนด bucket ค่อนข้างง่าย (แค่สองบรรทัด) การกำหนด Amazon EC2 instance ซับซ้อนกว่า เพราะต้องใช้ทรัพยากรที่เกี่ยวข้อง เช่น AMI, security group และ subnet
แต่ก่อนอื่น คุณจะเพิ่มพารามิเตอร์พิเศษที่ใช้ให้ค่าของ Amazon Machine Image (AMI)

=== P006
- 24. อัปเดต template โดยเพิ่มบรรทัดเหล่านี้ในส่วน **Parameters**:
```
  AmazonLinuxAMIID:
    Type: AWS::SSM::Parameter::Value<AWS::EC2::Image::Id>
    Default: /aws/service/ami-amazon-linux-latest/amzn2-am
```
> หมายเหตุผู้แปล: บรรทัด Default ถูกตัดท้ายในต้นฉบับ PDF ค่าเต็มที่น่าจะเป็น (ข้อความถัดไประบุว่าเป็น Amazon Linux 2 – โปรดตรวจกับหน้าแล็บจริง): `Default: /aws/service/ami-amazon-linux-latest/amzn2-ami-hvm-x86_64-gp2`
  - พารามิเตอร์นี้ใช้ AWS Systems Manager Parameter Store ดึง AMI ล่าสุด (ระบุในพารามิเตอร์ Default ซึ่งในกรณีนี้คือ Amazon Linux 2) ของ region ที่ stack อยู่ ทำให้ deploy stacks ใน regions ต่าง ๆ ได้ง่าย โดยไม่ต้องระบุ AMI ID ของแต่ละ region เอง
  - รายละเอียดเพิ่มเติมของวิธีนี้ ดูได้ที่: AWS Compute Blog: Query for the latest Amazon Linux AMI IDs using AWS Systems Manager Parameter Store (http://aws.amazon.com/blogs/compute/query-for-the-latest-amazon-linux-ami-ids-using-aws-systems-manager-parameter-store/)
เมื่อเขียน CloudFormation templates คุณอ้างอิงทรัพยากรอื่นใน template ได้ด้วยคีย์เวิร์ด **!Ref** ตัวอย่างเช่น นี่คือส่วนหนึ่งของ template task1.yaml ที่กำหนด VPC แล้วอ้างอิง VPC ในการกำหนด Route Table:
```
  VPC:
    Type: AWS::EC2::VPC
    Properties:
      CidrBlock: 10.0.0.0/16

  PublicRouteTable:
    Type: AWS::EC2::RouteTable
    Properties:
      VpcId: !Ref VPC
```
สังเกตว่าใช้ `!Ref VPC` อ้างอิงทรัพยากร VPC คุณจะใช้เทคนิคนี้เมื่อกำหนด EC2 instance
- 25. ใช้เคล็ดลับด้านล่างอัปเดต template เพื่อเพิ่ม Amazon EC2 instance ที่มี Properties ต่อไปนี้:
  - **ImageId:** อ้างอิง AmazonLinuxAMIID ซึ่งเป็นพารามิเตอร์ที่เพิ่มในขั้นก่อนหน้า
  - **InstanceType:** t2.micro
  - **SecurityGroupIds:** อ้างอิง AppSecurityGroup ซึ่งกำหนดไว้ในส่วนอื่นของ template
  - **SubnetId:** อ้างอิง PublicSubnet ซึ่งกำหนดไว้ในส่วนอื่นของ template

  - **Tags:** ใช้บล็อก YAML นี้:
```
      Tags:
        - Key: Name
          Value: App Server
```
เคล็ดลับบางประการ:
- ใช้หน้าเอกสารนี้ช่วย: AWS::EC2::Instance (https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/aws-properties-ec2-instance.html)
  - ใช้เวอร์ชัน YAML
- โค้ดของคุณควรอยู่ใต้หัวข้อ **Resources:** ในไฟล์ template
- เพิ่มเฉพาะ Properties ห้าตัวที่ระบุข้างต้น ไม่ต้องใส่คุณสมบัติอื่น
- เมื่ออ้างอิงทรัพยากรอื่นใน template เดียวกัน ให้ใช้ `!Ref` – ดูตัวอย่างตอนต้นของงานนี้
- เมื่ออ้างอิง **SecurityGroupIds** template ต้องการรายการ (list) ของ security groups จริง ๆ คุณจึงต้องเขียน security group เป็นรายการแบบนี้:
```
      SecurityGroupIds:
        - !Ref AppSecurityGroup
```
