=== P027
# นโยบายการ terminate ของ EC2 Auto Scaling (termination policy)
Auto Scaling termination policy:
- กำหนดว่า instance ใดจะถูก terminate เมื่อลดขนาดลง (scale in)
- กำหนดลำดับการ terminate ตามปัจจัยต่อไปนี้:
  - Availability Zone ที่มีจำนวน instances มากที่สุด
  - หลายนโยบาย (นโยบายจะถูกรันตามลำดับที่ระบุไว้)
แผนภาพ: Scale Out – เพิ่ม instance ใหม่ (New Instance Added) เข้า Auto Scaling group; Scale In – นำ instance ออก (Instance is Removed) จาก Auto Scaling group

=== P028
# นโยบายการ terminate (Termination policies)
| Termination Policy | คำอธิบาย (Description) |
| OldestInstance | เลือก instance ที่ทำงานนานที่สุด |
| NewestInstance | เลือก instance ที่ทำงานสั้นที่สุด |
| OldestLaunchConfiguration | terminate instance ที่มี configuration เก่าที่สุด (ค่าเริ่มต้น – default) |
| ClosestToNextInstanceHour | terminate instance ที่ใกล้ถึงชั่วโมงคิดเงินถัดไปที่สุด (ค่าเริ่มต้น – default) |

=== P029
# การสร้างกลุ่มแบบสถานะคงที่ (steady-state group)
กลุ่มแบบสถานะคงที่:
- ตั้งค่า EC2 Auto Scaling group ให้ค่า min, max และ desired เท่ากัน
- instance จะถูกสร้างใหม่โดยอัตโนมัติหากไม่สมบูรณ์ (unhealthy) หรือหาก Availability Zone ล้มเหลว
- ยังอาจมีช่วงหยุดทำงาน (downtime) ระหว่างรีไซเคิล instance
กรณีการใช้งาน: รักษา NAT server แบบสถานะคงที่ในแต่ละ Availability Zone
แผนภาพ: Auto Scaling group ที่มี Instance เดียว: Min = 1, Max = 1, Desired = 1

=== P031
# การขยายขนาดแบบไดนามิก (Dynamic scaling): Amazon EC2
- **Target Tracking Scaling:** เพิ่มหรือลดความจุปัจจุบันของกลุ่มตามค่าเป้าหมายของ metric ที่ระบุ
- **Step Scaling:** เพิ่มหรือลดความจุปัจจุบันของกลุ่มตามชุดการปรับขนาด (scaling adjustments) ซึ่งขึ้นกับขนาดของการละเมิดเกณฑ์ alarm (alarm breach)
- **Simple Scaling:** เพิ่มหรือลดความจุปัจจุบันของกลุ่มตามการปรับขนาดเพียงครั้งเดียว

=== P032
# การขยายขนาดเชิงคาดการณ์ (Predictive scaling): Amazon EC2
Predictive scaling:
- คาดการณ์โหลด (Forecast load)
- กำหนดตารางความจุขั้นต่ำ (Schedule minimum capacity)
กรณีการใช้งาน:
- ใช้ร่วมกับ dynamic scaling แบบ target tracking
- แอปพลิเคชันที่มีโหลดพุ่งขึ้นเป็นรอบ ๆ (periodic spikes)

=== P033
# ประเด็นสำคัญ (Key Takeaway)
- Amazon EC2 Auto Scaling ช่วยรักษาความพร้อมใช้งานของแอปพลิเคชันด้วยการเพิ่มหรือลด EC2 instances โดยอัตโนมัติตามเงื่อนไขที่กำหนด
- EC2 Auto Scaling ประกอบด้วยสามส่วน:
  - Launch configuration / launch template
  - Auto Scaling group
  - Scaling policies
- การขยายขนาดอิงได้กับ:
  - สุขภาพของ instance
  - Amazon CloudWatch alarms
  - ตารางเวลาหรือการใช้งานในอดีต (การคาดการณ์)
- การสร้าง launch configuration ต้องระบุรายละเอียดหลายอย่าง

# หลีกเลี่ยงการขยาย/ลดขนาดกลับไปกลับมา (Avoid thrashing)
**ช่วงเวลาที่ alarm ต้องคงอยู่ (Alarm sustain period):**
- ตัวอย่าง: CPU utilization > 90% นาน 10 นาที
**ช่วงพัก (Cooldown period):**
- เมื่อทำการ scale in หรือ out ให้ระงับกิจกรรมการปรับขนาดเพิ่มเติมเป็นระยะเวลาหนึ่ง
- ใช้กับ simple scaling policies
- ตัวอย่าง: ระงับการปรับขนาด 5 นาที
**ช่วงอุ่นเครื่องของ instance (Instance warmup period):**
- จำนวนวินาทีที่ instance ที่เพิ่ง launch ใช้ในการอุ่นเครื่อง
- ใช้กับ step scaling policies
- ตัวอย่าง: อุ่นเครื่องใช้เวลา 5 นาที

# Amazon Route 53
Amazon Route 53:
- เป็นเว็บเซอร์วิส Domain Name System (DNS) ที่ขยายขนาดได้
- กระจายทราฟฟิกข้าม Regions
- รองรับความพร้อมใช้งานสูงและความหน่วงต่ำ
ความสามารถ:
- จดทะเบียนหรือโอนย้ายชื่อโดเมน
- แปลงชื่อโดเมนเป็น IP addresses
- กำหนดเส้นทางคำขอตามความหน่วง (latency), health checks, น้ำหนัก (weights) ฯลฯ

=== P047
# การผูกชื่อ DNS กับ ELB
- ชื่อ DNS เริ่มต้นจาก ELB:
  - AWS กำหนด hostname ให้ load balancer ของคุณ ซึ่งแปลงเป็นชุดของ IP addresses
  - ตัวอย่าง: web-app.us-west-2.elb.amazonaws.com
- ผูกชื่อ DNS ของคุณเอง:
  - กำหนด hostname ของคุณเองผ่าน alias resource record set
  - สร้าง CNAME record ที่ชี้ไปยัง load balancer ของคุณ
  - ตัวอย่าง: example.com → ALIAS → web-app.us-west-2.elb.amazonaws.com

=== P048
# นโยบายการกำหนดเส้นทางของ Amazon Route 53 (routing policies)
Amazon Route 53 รองรับนโยบายการกำหนดเส้นทางเจ็ดแบบต่อไปนี้:
- 1. Simple routing policy (แบบง่าย)
- 2. Weighted routing policy (ตามน้ำหนัก)
- 3. Latency routing policy (ตามความหน่วง)
- 4. Failover routing policy (สลับไปยังระบบสำรอง)
- 5. Geolocation routing policy (ตามตำแหน่งที่มาของ DNS query)
- 6. Geoproximity routing policy (ส่งทราฟฟิกไปยัง AWS Region หรือตามละติจูดและลองจิจูด)
- 7. Multivalue answer routing policy (ตอบหลายค่า)
(แผนภาพ: Amazon Route 53 ส่งทราฟฟิกไปยัง Elastic Load Balancing (ELB) ที่ตำแหน่งต่าง ๆ)
