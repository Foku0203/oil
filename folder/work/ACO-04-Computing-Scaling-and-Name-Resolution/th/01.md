# โมดูล 4: การประมวลผล (การขยายขนาดและการแปลงชื่อ)
Elastic Load Balancing (ELB)

=== P008
# Elastic Load Balancing (ELB)
บริการกระจายโหลดแบบมีผู้ดูแลให้ (managed) ที่กระจายทราฟฟิกของแอปพลิเคชันขาเข้าไปยัง Amazon EC2 instances, containers และ IP addresses หลายตัว
แผนภาพ: ทราฟฟิกผู้ใช้ (User traffic) → Elastic Load Balancing (ELB) → App × 3

=== P009
# ประเภทของ load balancer: ALB
**Application Load Balancer (ALB)** – HTTP, HTTPS
- จัดการแอปพลิเคชันได้ยืดหยุ่น และรองรับ static IP address
- กระจายโหลดขั้นสูงสำหรับทราฟฟิก HTTP และ HTTPS
- รองรับโปรโตคอลมาตรฐานอุตสาหกรรม (WebSocket และ HTTP/2)
- ทำงานที่ระดับแอปพลิเคชัน (Layer 7)

=== P010
# ประเภทของ load balancer: NLB
**Network Load Balancer (NLB)** – TCP, UDP
- ประสิทธิภาพสูงสุดสำหรับแอปพลิเคชันของคุณ
- รองรับ static IP address
- กระจายโหลดของทราฟฟิก TCP หรือ UDP
- ทำงานที่ระดับการเชื่อมต่อ (Layer 4)

=== P011
# ประเภทของ load balancer: CLB
**Classic Load Balancer (CLB)** – รุ่นก่อนหน้า (PREVIOUS GENERATION) สำหรับ HTTP, HTTPS และ TCP
- สำหรับแอปพลิเคชันที่ใช้เครือข่าย EC2-Classic
- ทำงานทั้งที่ระดับคำขอ (request level) และระดับการเชื่อมต่อ (connection level)

=== P012
# ELB load balancer: คุณสมบัติ
ELB load balancers กระจายทราฟฟิกไปยังเป้าหมาย (targets) หลายตัวโดยอัตโนมัติ
- ความพร้อมใช้งานสูง (High availability – HA)
- การตรวจสุขภาพ (Health checks)
- คุณสมบัติด้านความปลอดภัย (Security features)
- การสิ้นสุด TLS (Transport Layer Security termination)
- การกระจายโหลดที่ layer 4 หรือ layer 7
- การเฝ้าติดตามการปฏิบัติงาน (Operational monitoring)

=== P013
# Load balancer: Listeners
แผนภาพ: Load balancer → Listener → Rule → Target Group (example.com) ที่มี Target หลายตัว พร้อม Health check
**Listeners:**
- กระบวนการที่กำหนดพอร์ตและโปรโตคอลที่ load balancer รอรับ (listen)
- load balancer แต่ละตัวต้องมี listener อย่างน้อยหนึ่งตัวเพื่อรับทราฟฟิก
- load balancer หนึ่งตัวมี listener ได้สูงสุด 50 ตัว
- กฎการกำหนดเส้นทาง (routing rules) ถูกกำหนดไว้บน listeners

=== P014
# Load balancer: Target groups
แผนภาพ: Load balancer → Listener → Rule → Target Group (example.com) ที่มี Target หลายตัว พร้อม Health check
**Target groups:**
- กลุ่มของเป้าหมายที่ลงทะเบียนไว้ ซึ่งรองรับ:
  - EC2 instances
  - ECS container instances
- เป้าหมายตัวเดียวลงทะเบียนกับหลาย target group ได้

=== P015
# ส่วนประกอบของ Application Load Balancer
แผนภาพ: Load Balancer มี Listener หลายตัว แต่ละ listener มี Rule หลายข้อ ส่งไปยัง target groups ต่าง ๆ แต่ละกลุ่มมี Target และ Health check ของตนเอง:
- Target group (example.com)
- Target group (example.com/blog)
- Target group (example.com/mobile)

=== P016
# ตัวอย่าง Application Load Balancer
แผนภาพ: www.example.com → Elastic Load Balancing (ELB) → กระจายตามเส้นทาง (path) ไปยัง Availability Zone A และ B:
- /orders → Orders (ทั้งสอง AZ)
- /images → Images (ทั้งสอง AZ)
- /registration → Reg (ทั้งสอง AZ)

=== P017
# สร้าง Application Load Balancer: AWS CLI
1. ใช้คำสั่ง create-load-balancer เพื่อสร้าง load balancer คุณต้องระบุ subnet สองตัวที่ไม่ได้อยู่ใน Availability Zone เดียวกัน
```
aws elbv2 create-load-balancer \
--name my-load-balancer \
--subnets subnet-12345678 subnet-23456789 \
--security-groups sg-12345678
```

=== P018
# สร้าง target group สำหรับ load balancer
2. ใช้คำสั่ง create-target-group เพื่อสร้าง target group คุณต้องระบุ Amazon VPC ที่ EC2 instances ของคุณทำงานอยู่
```
aws elbv2 create-target-group \
--name my-targets \
--protocol HTTP \
--port 80 \
--vpc-id vpc-12345678
```

=== P019
# ลงทะเบียน EC2 instances เข้า target group
3. ใช้คำสั่ง register-targets เพื่อลงทะเบียน instances ของคุณเข้ากับ target group
```
aws elbv2 register-targets \
--target-group-arn targetgroup-arn \
--targets Id=i-12345678 Id=i-23456789
```

=== P020
# ลงทะเบียน EC2 instances เข้า target group (สร้าง listener)
4. ใช้คำสั่ง create-listener เพื่อสร้าง listener ให้ load balancer โดย listener มีกฎเริ่มต้น (default rule) ที่ส่งต่อคำขอไปยัง target group ของคุณ
```
aws elbv2 create-listener \
--load-balancer-arn loadbalancer-arn \
--protocol HTTP \
--port 80 \
--default-actions Type=forward,TargetGroupArn=targetgroup-arn
```

=== P021
# ตรวจสอบสุขภาพของเป้าหมายที่ลงทะเบียนไว้
5. (ไม่บังคับ) ตรวจสอบสุขภาพของเป้าหมายที่ลงทะเบียนใน target group ด้วยคำสั่ง describe-target-health
```
aws elbv2 describe-target-health --target-group-arn targetgroup-arn
```

=== P022
# ประเด็นสำคัญ (Key Takeaway)
- load balancer มีสามประเภท:
  - Application load balancers
  - Network load balancers
  - Classic load balancers
- listener แต่ละตัวตรวจหาคำขอเชื่อมต่อจากไคลเอนต์ แล้วส่งต่อคำขอไปยัง target group หนึ่งกลุ่มหรือมากกว่าตามกฎที่กำหนด
- แต่ละกฎระบุ target group, เงื่อนไข (condition) และลำดับความสำคัญ (priority)

=== P023
# โมดูล 4: การประมวลผล (การขยายขนาดและการแปลงชื่อ)
Amazon EC2 Auto Scaling

=== P024
# Amazon EC2 Auto Scaling
Amazon EC2 Auto Scaling:
- launch หรือ terminate Amazon EC2 instances โดยอัตโนมัติตาม:
  - การตรวจสถานะสุขภาพ (Health status checks)
  - นโยบายที่ผู้ใช้กำหนดซึ่งขับเคลื่อนด้วย Amazon CloudWatch
  - ตารางเวลา (Schedules)
  - เกณฑ์อื่น ๆ (เช่น ผ่านโปรแกรม)
  - สั่งเองด้วย set-desired-capacity
- ขยายออก (scale out) เพื่อรองรับความต้องการ และลดขนาดลง (scale in) เพื่อลดต้นทุน

=== P025
# EC2 Auto Scaling ขณะทำงาน
**Launch Configuration / Launch Template** – การตั้งค่าของ instance ที่จะ launch ระบุ:
- AMI
- Instance type
- Security group
- Instance key pair
- พื้นที่จัดเก็บ (Storage)
- IAM roles
- User data
มี launch configuration ที่ใช้งานได้ครั้งละหนึ่งตัวเท่านั้น
**EC2 Auto Scaling Group** – กลุ่มเชิงตรรกะของ EC2 instances
- ขยาย/ลดขนาดอัตโนมัติระหว่าง: Minimum (ต่ำสุด), Desired (ที่ต้องการ – ไม่บังคับ), Maximum (สูงสุด)
- ผสานรวมกับ Elastic Load Balancing (ไม่บังคับ)
- ตรวจสุขภาพเพื่อรักษาขนาดกลุ่ม
- กระจายและถ่วงดุล instances ข้าม Availability Zones
**EC2 Auto Scaling Policy** – พารามิเตอร์สำหรับการทำงานของ Amazon EC2 Auto Scaling
- ทริกเกอร์ policies อย่างไร? Amazon CloudWatch, instance ล้มเหลว (health check), ตามตารางเวลา, สั่งเอง
- ขยายออกหรือลดลง และมากเท่าใด:
  - ChangeInCapacity (+/-#)
  - ExactCapacity(#)
  - ChangeInPercent (+/-%)
  - ช่วงพัก (Cooldown period) – สำหรับ simple scaling
  - ช่วงอุ่นเครื่อง (Warmup period) – สำหรับ step scaling

=== P026
# EC2 Auto Scaling และสุขภาพของ instance
- เก็บสถานะสุขภาพของ instances
- terminate instances ที่ถูกระบุว่าไม่สมบูรณ์ (unhealthy)
- ใช้การตรวจสถานะของ Amazon EC2 instance เป็นค่าเริ่มต้น
- ตั้งค่าการตรวจเหล่านี้ได้หาก instances อยู่หลัง load balancer:
  - การตรวจ instance ของ load balancer
  - การตรวจ instance ของ Amazon EC2
- ทริกเกอร์การรีไซเคิล instance ได้ด้วยสคริปต์ภายนอก: คำสั่ง `aws autoscaling set-instance-health`
