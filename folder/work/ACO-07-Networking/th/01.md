# โมดูล 7: เครือข่าย
เครือข่ายของ AWS Cloud และ Amazon Virtual Private Cloud (Amazon VPC)

=== P006
# เครือข่ายของ AWS Cloud
แผนภาพ: AWS Cloud → VPC ที่มี EC2 instances และ Amazon RDS instance (AWS Network, Private IP Address Space: 10.50.0.0 – 10.50.255.255) เชื่อมต่อกับ:
- ศูนย์ข้อมูลขององค์กร (Corporate data center)
- VPC รอง (Secondary VPC)
- Internet

=== P007
# ส่วนประกอบเครือข่ายของ AWS
แผนภาพ (AWS Cloud → VPC ที่มี Availability Zone 1 และ 2 และ Router):
- Public subnet: EC2 instances ใน security group มี Primary network interface (elastic network interface) เชื่อมกับ Internet gateway ให้ Internet client เข้าถึงได้
- Private subnet: EC2 instances แต่ละตัวอยู่ใน security group ของตน
- Corporate client ในศูนย์ข้อมูลขององค์กร → Customer gateway → VPN connection → Virtual private gateway → VPC

=== P008
# Amazon VPC
Amazon VPC คือเครือข่ายเสมือนที่จัดเตรียมไว้ในส่วนที่แยกออกจากกันในเชิงตรรกะของ AWS Cloud:
- รองรับการแยกเชิงตรรกะด้วย subnets
- ให้ความปลอดภัยแบบละเอียด
- รองรับ hardware virtual private network (VPN) เป็นทางเลือก

=== P009
# การตั้งค่า Amazon VPC: การกำหนด IP address
การกำหนด IP address:
- ช่วง IP address แบบ private ที่ถูกต้องตามที่ RFC 1918 กำหนด
- ใน Amazon VPC คุณกำหนดเครือข่ายได้เฉพาะระหว่าง /16 ถึง /28
- ใช้ช่วง IP address ที่ไม่ทับซ้อนกัน
> **แนวปฏิบัติที่ดีที่สุด (Best Practice):** จำกัด VPC ให้อยู่ในช่วงที่ RFC1918 กำหนด เพื่อหลีกเลี่ยงปัญหาการกำหนดเส้นทางที่อาจเกิดขึ้น

=== P010
# ตัวอย่างคำสั่ง CLI สำหรับสร้าง VPC


=== P011
# สัญกรณ์ Classless Inter-Domain Routing (CIDR)
รูปแบบ IP address: `x.x.x.x/n` โดย x.x.x.x คือ IP address ประกอบด้วย network prefix (ส่วนเครือข่าย) และ host identifier (ส่วนระบุโฮสต์) ส่วน /n คือความยาวของ prefix
| CIDR block | การแทนด้วยบิต (Bit representation) | ช่วง address ที่สอดคล้อง |
| 10.50.1.0/24 | 00001010.00110010.00000001.xxxxxxxx | 10.50.1.0 – 10.50.1.255 |
| 10.50.1.0/27 | 00001010.00110010.00000001.000xxxxx | 10.50.1.0 – 10.50.1.31 |
| 10.50.1.132/32 | 00001010.00110010.00000001.10000100 | 10.50.1.132 (address เดียว) |
| 0.0.0.0/0 | xxxxxxxx.xxxxxxxx.xxxxxxxx.xxxxxxxx | 0.0.0.0 – 255.255.255.255 (ทุก address) |

=== P012
# IP addresses ที่ Amazon VPC สงวนไว้
| CIDR Block | เหตุผล (Rationale) |
| 10.0.0.0 | Network address (address ของเครือข่าย) |
| 10.0.0.1 | AWS สงวนไว้เป็น address ของเราเตอร์ของ VPC |
| 10.0.0.2 | IP address ของ DNS server จะเป็นค่าฐานของช่วงเครือข่าย VPC บวกสองเสมอ อย่างไรก็ตาม VPC ยังสงวนค่าฐานของแต่ละช่วง subnet บวกสองไว้ด้วย |
| 10.0.0.3 | AWS สงวนไว้ใช้ในอนาคต |
| 10.0.0.255 | Network broadcast address – AWS ไม่รองรับ broadcast ใน VPC จึงสงวน address นี้ไว้ |

=== P016
# คุณสมบัติ auto-assign public IP ของ subnet
- เฉพาะ instances ที่ launch ใน Amazon VPC ค่าเริ่มต้น (default VPC) เท่านั้นที่ได้รับ public IP address ตอนสร้าง
- instances ที่สร้างใน VPC ที่กำหนดเอง (custom VPC) ต้องแก้ค่าเริ่มต้นจึงจะได้รับ public IP address
- อีกทางหนึ่ง ตั้งค่า Modify auto-assign IP settings บน subnets ให้กำหนด public IP address ให้ instances อัตโนมัติ
- public IP address ไม่คงที่ ต่างจาก Elastic IP address

=== P018
# ส่วนประกอบของ Amazon VPC: Elastic network interfaces
elastic network interface คือ network interface เสมือน (NIC) ที่ต่อกับ Amazon EC2 instance
(แผนภาพ: instance ใน Security group มี Primary network interface (elastic network interface), Elastic network interface 2 และ Elastic network interface 3)
- instance แต่ละตัวมี elastic network interface หลัก (primary) ที่ถอดออกไม่ได้
- คุณต่อ network interfaces เพิ่มเข้ากับ instance ได้
- กรณีการใช้งาน ได้แก่:
  - ใช้อุปกรณ์เครือข่ายและอุปกรณ์ความปลอดภัย (appliances) ใน VPC
  - เชื่อม instance กับบริการที่ขับเคลื่อนด้วย AWS PrivateLink

=== P021
# ประเด็นสำคัญ (Key Takeaways)
- Amazon VPC ช่วยจัดเตรียมเครือข่ายที่แยกออกจากกันเชิงตรรกะบน AWS

=== P024
# Network address translation (NAT)
**ความท้าทาย (Challenge):** Amazon EC2 instance ใน private subnet ต้องเชื่อมต่ออินเทอร์เน็ต (เช่น เพื่ออัปเดตซอฟต์แวร์ – Software updates)
**ทางแก้ (Solutions):**
- ✓ NAT gateway
- ✓ NAT instance
แผนภาพ: Private instance 10.50.2.191 ใน Security group ภายใน Private subnet 10.50.2.0/24 พยายามเชื่อมต่อ Internet แต่การเชื่อมต่อถูกบล็อก! (Connection is blocked!)

=== P025
# ลักษณะของ NAT gateway และขั้นตอนการสร้าง
**ลักษณะของ NAT gateway:**
- บริการที่ AWS ดูแลให้ (AWS managed service)
- มีความซ้ำซ้อน (redundancy) ในตัวภายใน availability zone
- ต้องใช้ Elastic IP address
- รองรับโปรโตคอล:
  - TCP, UDP และ ICMP
**ขั้นตอนการสร้าง:**
- 1. ระบุ (Specify): public subnet ที่ gateway จะอยู่ และ Elastic IP address
- 2. อัปเดต (Update): route tables ของ private subnets

=== P028
# การสร้างการเชื่อมต่อ VPC peering
ในการสร้างการเชื่อมต่อ VPC peering:
- 1. เจ้าของ VPC ฝั่งผู้ขอ (requester) ส่งคำขอเชื่อมต่อ VPC
- 2. เจ้าของ VPC ฝั่งผู้รับ (accepter) ยอมรับคำขอเชื่อมต่อ VPC
- 3. เจ้าของทั้งสองฝ่ายเพิ่มรายการใน route table ของทั้งสอง VPC ที่เข้าร่วม
- 4. หากจำเป็น เจ้าของปรับกฎ security group ในทั้งสอง VPC ที่เข้าร่วม
- 5. หากจำเป็น เจ้าของเปิดใช้การแปลง DNS hostname สำหรับการเชื่อมต่อ VPC
