=== S007
# การปฏิบัติการระบบ (Systems operations)
หน้าที่ความรับผิดชอบและงานของการปฏิบัติการระบบ
--- notes
เริ่มจากนิยามของการปฏิบัติการระบบ การปฏิบัติการระบบคือหน้าที่และงานที่จำเป็นในการสร้าง (build / create), ทดสอบ (test), deploy, เฝ้าติดตาม (monitor), ดูแลรักษา (maintain) และปกป้อง (safeguard) ระบบคอมพิวเตอร์ที่ซับซ้อน
กิจกรรม "build" ของการปฏิบัติการระบบรวมถึงการพัฒนาแม่แบบโครงสร้างพื้นฐานที่นำกลับมาใช้ซ้ำได้ (reusable infrastructure templates) ซึ่งจะถูกนำไปทดสอบ deploy เฝ้าติดตาม ดูแลรักษา และปกป้องต่อไป การพัฒนาแม่แบบโครงสร้างพื้นฐานที่นำกลับมาใช้ซ้ำได้นี้คือสิ่งที่อธิบายกิจกรรม "create" ของการปฏิบัติการระบบ

=== S008
# การปฏิบัติการระบบบนคลาวด์
**การทำงานอัตโนมัติของการปฏิบัติการระบบ (Automation of system operations)** ช่วยให้:
- deploy โครงสร้างพื้นฐานและแอปพลิเคชันได้ซ้ำ ๆ ตามต้องการ (on demand)
- สร้างระบบที่อธิบายตัวเองได้ (self-describing systems)
- สร้างระบบที่ปลอดภัยและผ่านการทดสอบมาอย่างดี
แผนภาพ: สคริปต์ โปรแกรม หรือแม่แบบ (Script, program, or template) → Development (พัฒนา) / Test (ทดสอบ) / Production (ใช้งานจริง)
--- notes
แทนที่จะสร้างทุกส่วนของการ deploy ระบบคอมพิวเตอร์ที่ซับซ้อนด้วยมือ ให้พิจารณาใช้ระบบอัตโนมัติ แนวปฏิบัติที่ดีที่สุด (best practice) คือการใช้ไฟล์หรือแอปพลิเคชันเพื่อบรรจุคำอธิบายของเครือข่ายและส่วนประกอบต่าง ๆ ที่จะทำงานในเครือข่ายนั้น คอร์สนี้จะลงลึกถึงความเป็นไปได้บางอย่างในการบรรจุโครงสร้างพื้นฐานที่นำกลับมาใช้ซ้ำได้
สำหรับการพูดคุยตอนนี้ ให้จำไว้ว่าระบบอัตโนมัติในระดับต่าง ๆ ทำได้โดยการสร้างสคริปต์ โปรแกรม หรือแม่แบบ เช่น:
- Linux shell script
- แอปพลิเคชัน Python หรือ Ruby
- แอปพลิเคชัน C#
- รูปแบบแม่แบบ เช่น AWS CloudFormation (จะกล่าวถึงอย่างละเอียดในคอร์สนี้)
เมื่อกำหนดโครงสร้างพื้นฐานแบบ declarative (ประกาศสิ่งที่ต้องการ) หรือแบบ programmatic (เขียนโปรแกรม) ผู้ใช้จะสามารถสร้างการ deploy ได้มากเท่าที่ต้องการ ในเวลาที่ต้องการ เป้าหมายคือทำให้การสร้างโครงสร้างพื้นฐานทำซ้ำได้ คุณสามารถ deploy โครงสร้างพื้นฐานที่กำหนดไว้ครั้งเดียวไปยัง Region ต่าง ๆ ได้อย่างง่ายดาย หรือสร้างสภาพแวดล้อมสำหรับพัฒนาและทดสอบที่ตรงกับสภาพแวดล้อม production อย่างสม่ำเสมอ

=== S010
# บริการ AWS ที่สำคัญสำหรับการปฏิบัติการระบบ: เครือข่าย (Network)
แผนภาพ 3 ด้าน: Network (เครือข่าย) / Compute (การประมวลผล) / Access (การเข้าถึง)
- **Amazon Virtual Private Cloud (Amazon VPC)** – เครือข่าย
  - เครือข่ายเสมือน (Virtual networks)
  - แยกออกจากกันในเชิงตรรกะ (Logically isolated)
  - คุณสมบัติหลักที่ตั้งค่าได้: ช่วง IP, การกำหนดเส้นทาง (routing), เกตเวย์ (gateways) และการตั้งค่าความปลอดภัย
- **Amazon Elastic Compute Cloud (Amazon EC2)** – การประมวลผล
  - สภาพแวดล้อมการประมวลผลเสมือน (Virtual computing environments)
  - Amazon Machine Images (AMIs)
  - ขยายขนาดได้ (Scalable)
  - ปรับแต่งให้เหมาะสมได้ (Optimizable)
- **AWS Identity and Access Management (IAM)** – การเข้าถึง
  - จัดการการเข้าถึงและการยืนยันตัวตน (authentication)
  - Users, groups, roles และ policies
  - Identity federation (การเชื่อมโยงตัวตน)
*บริการเหล่านี้จะกล่าวถึงอย่างละเอียดในภายหลัง
--- notes
งาน 3 ด้านหลักที่สำคัญต่อการปฏิบัติการระบบ คือ เครือข่าย การประมวลผล และการควบคุมการเข้าถึง
เมื่อผู้ใช้ตั้งค่าสภาพแวดล้อมเครือข่ายบนคลาวด์ บริการที่ใช้คือ Amazon Virtual Private Cloud (Amazon VPC) โดย virtual private cloud หรือ VPC คือสภาพแวดล้อมเครือข่ายที่ทรัพยากรต่าง ๆ จะถูก launch เข้าไป เช่น EC2 instances VPC ถูกออกแบบมาเพื่อให้ควบคุมการแยกสภาพแวดล้อมและทรัพยากรออกจากกันได้มากขึ้น
แต่ละ VPC ถูกกำหนดอยู่ภายใน Region หนึ่ง คุณสามารถมีหลาย VPC ในแต่ละ Region และมี VPC ได้ในกี่ Region ก็ได้ตามต้องการ subnet ที่คุณกำหนดภายใน VPC จะเป็นแบบ public หรือ private ก็ได้

AWS มีตัวเลือกด้านการประมวลผลหลายแบบ Amazon EC2 ช่วยให้คุณจัดเตรียม (provision) สภาพแวดล้อมการประมวลผลเสมือนบนคลาวด์ได้ แทบทุกอย่างที่ทำได้ด้วยเซิร์ฟเวอร์ ก็ทำได้ด้วย Amazon EC2 instance
รองรับระบบปฏิบัติการเซิร์ฟเวอร์ส่วนใหญ่ ได้แก่ Windows, Red Hat, SUSE, Ubuntu และ Amazon Linux ผู้ใช้สามารถสร้างอิมเมจ (image) ของเซิร์ฟเวอร์ได้ทุกเมื่อด้วยการคลิกไม่กี่ครั้งหรือเรียก API ง่าย ๆ อิมเมจเหล่านี้เรียกว่า Amazon Machine Images (AMIs) และนำกลับมาใช้ launch instance ในอนาคตได้ Amazon EC2 ขยายขนาดได้สูง หมายความว่าจะเพิ่ม instance เมื่อจำเป็น และยุติ (terminate) instance เหล่านั้นเมื่อไม่จำเป็น Amazon EC2 ยังปรับแต่งให้เหมาะสมได้ เพราะสามารถเลือกประเภท instance (instance type) ให้เหมาะกับ CPU, หน่วยความจำ, พื้นที่จัดเก็บ, ความสามารถด้านเครือข่าย หรือกราฟิก รวมทั้งแบบใช้งานทั่วไป (general purpose) แต่ละประเภท instance ที่ปรับแต่งแล้วมีหลายขนาดให้เลือก

=== S012
# บริการ AWS ที่สำคัญสำหรับการปฏิบัติการระบบ: การเข้าถึง (Access)
แผนภาพ 3 ด้าน: Network (เครือข่าย) / Compute (การประมวลผล) / Access (การเข้าถึง)
- **Amazon Virtual Private Cloud (Amazon VPC)** – เครือข่าย
  - เครือข่ายเสมือน (Virtual networks)
  - แยกออกจากกันในเชิงตรรกะ (Logically isolated)
  - คุณสมบัติหลักที่ตั้งค่าได้: ช่วง IP, การกำหนดเส้นทาง (routing), เกตเวย์ (gateways) และการตั้งค่าความปลอดภัย
- **Amazon Elastic Compute Cloud (Amazon EC2)** – การประมวลผล
  - สภาพแวดล้อมการประมวลผลเสมือน (Virtual computing environments)
  - Amazon Machine Images (AMIs)
  - ขยายขนาดได้ (Scalable)
  - ปรับแต่งให้เหมาะสมได้ (Optimizable)
- **AWS Identity and Access Management (IAM)** – การเข้าถึง
  - จัดการการเข้าถึงและการยืนยันตัวตน (authentication)
  - Users, groups, roles และ policies
  - Identity federation (การเชื่อมโยงตัวตน)
*บริการเหล่านี้จะกล่าวถึงอย่างละเอียดในภายหลัง
--- notes
สุดท้ายคือการจัดการการเข้าถึง AWS Identity and Access Management (IAM) เป็นบริการที่ช่วยให้ผู้ใช้ควบคุมการเข้าถึงทรัพยากร AWS ได้อย่างปลอดภัย ทั้งสำหรับผู้ใช้และโปรแกรม ผู้ใช้ใช้ IAM เพื่อควบคุมว่าใครใช้ทรัพยากร AWS ได้บ้าง (การยืนยันตัวตน – authentication) และใช้ทรัพยากรใดได้บ้างด้วยวิธีใด (การให้สิทธิ์ – authorization)
IAM รองรับการควบคุมสิทธิ์การเข้าถึงแบบละเอียด ไม่ใช่แค่ระดับทรัพยากร แต่ลงลึกไปถึงการกำหนดว่าเรียก API ใดได้บ้างในแต่ละบริการ
ใช้ IAM เพื่อสร้างผู้ใช้เพิ่มและกำหนดสิทธิ์ให้ผู้ใช้เหล่านั้นตามหลักสิทธิ์น้อยที่สุด (least-privilege principle) ด้วย IAM คุณสามารถควบคุมการเข้าถึงบริการและทรัพยากร AWS สำหรับผู้ใช้ในบัญชี AWS ได้อย่างปลอดภัย ตัวอย่างเช่น หากคุณต้องการสิทธิ์ระดับผู้ดูแลระบบ (administrator) คุณสามารถสร้าง IAM user ให้สิทธิ์เข้าถึงเต็มรูปแบบแก่ผู้ใช้นั้น แล้วใช้ credentials นั้นในการทำงานกับ AWS ภายหลังหากจำเป็นต้องเพิกถอนหรือแก้ไขสิทธิ์ ก็สามารถลบหรือแก้ไข policy ใด ๆ ที่ผูกกับ IAM user นั้นได้ นอกจากนี้ หากมีผู้ใช้หลายคนที่ต้องเข้าถึงบัญชี AWS คุณสามารถสร้าง credentials เฉพาะของแต่ละคนและกำหนดว่าใครเข้าถึงทรัพยากรใดได้บ้าง กล่าวคือไม่จำเป็นต้องแชร์ credentials ร่วมกัน ตัวอย่างเช่น คุณสามารถสร้าง IAM users ที่มีสิทธิ์อ่านอย่างเดียว (read-only) ต่อทรัพยากรในบัญชี AWS แล้วแจก credentials เหล่านั้นให้ผู้ใช้ที่ต้องการสิทธิ์อ่าน
Identity federation เป็นอีกเครื่องมือที่มีประโยชน์ซึ่งใช้ร่วมกับ IAM ได้ ด้วย federation ผู้ใช้สามารถใช้ single sign-on (SSO) เพื่อเข้าถึงบัญชี AWS โดยใช้ credentials จากไดเรกทอรีขององค์กร federation ใช้มาตรฐานเปิด เช่น Security Assertion Markup Language 2.0 (SAML) เพื่อแลกเปลี่ยนข้อมูลตัวตนและความปลอดภัยระหว่างผู้ให้บริการตัวตน (identity provider – IdP) กับแอปพลิเคชัน
