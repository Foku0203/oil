=== S023
# แนวปฏิบัติที่ดีที่สุดของ IAM (IAM best practices)
**แนวปฏิบัติที่ดีที่สุด (Best practice):**
- หลีกเลี่ยงการใช้ root credentials ในการดูแลระบบประจำวัน
- มอบหมายงานด้านการดูแลระบบตามหลักสิทธิ์น้อยที่สุด (least-privilege)
- ใช้ IAM roles เพื่อให้การเข้าถึงข้ามบัญชี (cross-account access)
- ใช้ MFA เพื่อเพิ่มความปลอดภัยของบัญชีอีกระดับ
--- notes
แนวปฏิบัติที่ดีที่สุดบางประการของ IAM มีดังนี้:
- หลีกเลี่ยงการใช้ credentials ของบัญชี root ในการดูแลระบบประจำวัน แทนที่จะเป็นเช่นนั้น เมื่อตั้งค่าบัญชีใหม่ ให้กำหนด IAM user ใหม่อย่างน้อยหนึ่งคน แล้วให้สิทธิ์ผู้ใช้เหล่านั้น เพื่อให้งานประจำวันส่วนใหญ่ทำได้ด้วย credentials ของ IAM user
- มอบหมายงานด้านการดูแลระบบตามหลักสิทธิ์น้อยที่สุด ให้สิทธิ์เข้าถึงเฉพาะบริการที่จำเป็น และจำกัดสิทธิ์ภายในบริการเหล่านั้นให้เหลือเฉพาะส่วนที่จำเป็น สามารถให้สิทธิ์เพิ่มเติมได้เสมอเมื่อเวลาผ่านไปหากมีความจำเป็น
- ใช้ IAM roles เพื่อให้การเข้าถึงข้ามบัญชี แนวปฏิบัติที่ดีอื่น ๆ ของ IAM ที่กล่าวไว้ก่อนหน้าในโมดูลนี้ ได้แก่ การตั้งค่านโยบายรหัสผ่านที่รัดกุม การเปิดใช้ MFA สำหรับผู้ใช้ที่มีสิทธิ์สูง และการหมุนเวียน (rotate) credentials อย่างสม่ำเสมอ รายการแนวปฏิบัติที่ดีที่สุดทั้งหมดของ IAM ดูได้ที่ https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html
- MFA เป็นแนวปฏิบัติที่ดีที่ควรใช้เพื่อความปลอดภัย

=== S028
# สามวิธีในการใช้ AWS
- **AWS Management Console** – อินเทอร์เฟซแบบกราฟิก
- **AWS Command Line Interface (AWS CLI)** – เครื่องมือบรรทัดคำสั่ง (CLI)
- **Software Development Kits (SDKs)** – เรียกใช้ APIs จากภาษาโปรแกรมหลักส่วนใหญ่ (APIs from most major programming languages)
--- notes
มีสามทางเลือกในการเข้าถึงบริการ AWS ทั้งสามทางสร้างอยู่บน API แบบคล้าย REST ร่วมกัน ซึ่งเป็นรากฐานของ AWS
AWS Management Console มีอินเทอร์เฟซแบบกราฟิกที่ครบครันสำหรับผลิตภัณฑ์และบริการส่วนใหญ่ของ AWS บางครั้งคุณสมบัติใหม่อาจยังไม่เปิดให้ใช้ความสามารถทั้งหมดผ่านคอนโซลในช่วงที่เพิ่งเปิดตัว
AWS Command Line Interface (AWS CLI) เป็นชุดเครื่องมือที่รันได้จากโปรแกรมบรรทัดคำสั่งบน Linux, MacOS หรือ Windows
software development kits (SDKs) เป็นแพ็กเกจที่ AWS จัดให้ เพื่อให้เข้าถึงบริการ AWS ด้วยภาษาโปรแกรมยอดนิยม เช่น Python, Ruby, .NET หรือ Java SDKs ทำให้ใช้ AWS ในแอปพลิเคชันที่มีอยู่ได้อย่างตรงไปตรงมา และยังช่วยให้สร้างแอปพลิเคชันเพื่อ deploy และเฝ้าติดตามระบบที่ซับซ้อนได้ทั้งหมดผ่านโค้ด
AWS CLI และ SDKs ให้ความยืดหยุ่น ทำให้ผู้ใช้ AWS สร้างเครื่องมือของตนเองที่เฉพาะกับธุรกิจ และปรับแต่งคุณสมบัติที่มีอยู่ของ AWS ได้ ตัวอย่างเช่น ผู้ใช้อาจสร้างสคริปต์หรือแอปพลิเคชันของตนเองสำหรับ launch Amazon EC2 instances ที่บังคับให้ใช้ชุด AMIs เฉพาะ หรือเพิ่มชุด tags มาตรฐานให้กับทรัพยากรที่สร้างในบัญชี
AWS CLI เป็นวิธีที่ไม่ขึ้นกับภาษาโปรแกรมในการทำให้การ deploy ทรัพยากร AWS เป็นอัตโนมัติและทำซ้ำได้ เช่น ผ่าน Linux shell scripts หรือ Windows batch files
**หมายเหตุ (NOTE):** ทั้งสามโหมดการเข้าถึงใช้แทนกันได้ ตัวอย่างเช่น เซิร์ฟเวอร์ Amazon EC2 ที่สร้างผ่านการเรียก SDK สามารถดูรายละเอียดได้ด้วยคำสั่งบรรทัดคำสั่งที่เหมาะสม (`aws ec2 describe-instances`) และ EC2 instance นี้สามารถ terminate ภายหลังได้ด้วยการคลิกไม่กี่ครั้งใน AWS Management Console
**หมายเหตุ:** การเปลี่ยนแปลงที่ทำผ่าน AWS CLI หรือ API อาจใช้เวลาไม่กี่วินาทีหรือไม่กี่นาทีจึงจะปรากฏใน AWS Management Console

1. ในการติดตั้ง AWS CLI ด้วย pip ให้รันคำสั่งต่อไปนี้:
```
$ pip3 install awscli --upgrade –-user
```
สวิตช์ `--user` ใช้เพื่อติดตั้ง AWS CLI ไว้ใน `~/.local/bin`
2. ในการตรวจสอบการติดตั้ง ให้รันคำสั่งต่อไปนี้:
```
$ aws --version
```
ผลลัพธ์ที่คาดว่าจะได้คือ:
```
aws-cli/1.16.137 Python/3.7.3 Linux/4.14.77-81.59-amzn2.x86_64 botocore/1.12.127
```

ในการติดตั้ง AWS CLI (Linux) ให้ใช้ pip3 เพื่อให้แน่ใจว่าได้ AWS CLI เวอร์ชันล่าสุด

=== S030
# แนะนำ AWS CLI
**AWS Command Line Interface (CLI):**
- ใช้ได้บน Linux, Windows และ Mac
- ใช้คำสั่ง **aws configure** เพื่อกำหนดค่าเริ่มต้น
**ตัวเลือกรูปแบบผลลัพธ์ของ CLI (CLI output format options):**
- **Table** – มนุษย์อ่านง่าย (Human Readable), อยู่ในรูปตาราง (Tabular Form)
- **JSON** – รูปแบบค่าเริ่มต้น (Default format), เหมาะกับการนำผลลัพธ์ไปใช้ผ่านโปรแกรม (programmatic usage)
- **Text** – บรรทัดที่คั่นด้วย tab (Tab-delimited lines), เหมาะกับสคริปต์ bash หรือ Power Shell
```
$ aws configure
AWS Access Key ID [None]: AKIAIOSFODNN7EXAMPLE
AWS Secret Access Key [None]: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
Default region name [None]: us-west-2
Default output format [None]: json
```
--- notes
ต่อไปนี้คือการทบทวนข้อมูลพื้นฐานบางอย่างเกี่ยวกับ AWS CLI โดย AWS CLI ใช้ได้บนแพลตฟอร์ม Linux, Windows และ Mac สามารถติดตั้งบน EC2 instances ที่เป็น Linux และ Windows ได้ด้วย และติดตั้งมาให้แล้วโดยค่าเริ่มต้นบน Amazon Linux instances
หลังจากติดตั้ง AWS CLI แล้ว สามารถใช้คำสั่ง `aws configure` เพื่อตั้งค่าเริ่มต้นบางอย่างสำหรับทุกคำสั่งของ AWS CLI ค่าเริ่มต้นหลัก ๆ คือ access key ID และ secret access key ที่ผูกกับบัญชี IAM ที่คุณจะใช้เข้าถึงทรัพยากร AWS นอกจากนี้ยังสามารถกำหนด Region เริ่มต้นสำหรับทุกคำสั่งได้
รูปแบบข้อมูลผลลัพธ์เริ่มต้นคือเอกสาร JSON ซึ่งเหมาะที่สุดในกรณีที่ผลลัพธ์จะถูกจัดการผ่านโปรแกรม JSON เป็นมาตรฐานโดยพฤตินัย (de facto standard) สำหรับการจัดรูปแบบและแลกเปลี่ยนข้อมูลบนอินเทอร์เน็ต ซึ่งทั้งมนุษย์อ่านได้ง่ายและเครื่องแยกวิเคราะห์ (parse) ได้ง่าย ภาษาโปรแกรมและเฟรมเวิร์กหลักแทบทั้งหมดมีวิธีแปลงผลตอบกลับแบบ JSON เป็นออบเจกต์หรือ associative arrays
อย่างไรก็ตาม AWS CLI ยังรองรับรูปแบบผลลัพธ์อีกสองแบบ:
- ตารางแบบ ASCII (ASCII-formatted table) – รูปแบบตารางอ่านง่ายที่สุด เพราะข้อมูลแสดงในรูปที่มนุษย์อ่านได้ภายในตาราง คำสั่งคือ: `$ export AWS_DEFAULT_OUTPUT="table"`
- ข้อความคั่นด้วย tab (Tab-delimited text) – รูปแบบข้อความนี้แสดงข้อมูลเป็นข้อความในบรรทัดที่คั่นด้วย tab และทำงานได้ดีกับเครื่องมือประมวลผลข้อความของ Unix เช่น PowerShell scripts คำสั่งคือ: `output=text`
ข้อมูลเพิ่มเติมเกี่ยวกับการควบคุมผลลัพธ์ของคำสั่งเมื่อใช้ AWS CLI ดูได้ที่ https://docs.aws.amazon.com/cli/latest/userguide/cli-usage-output.html

# รูปแบบบรรทัดคำสั่ง (Command-line format)
ส่วนประกอบ: `aws` + Service (บริการ) + Operation (การดำเนินการ) + Parameters (พารามิเตอร์) + Options (ตัวเลือก)
```
aws ec2 stop-instances -–instance-id i-1234567890abcdef0 --output json
aws ec2 run-instances –-cli-input-json file://webserver.json
```
(ในแผนภาพ `ec2` คือ Amazon EC2)
คำสั่งดูความช่วยเหลือ:
```
$ aws help
$ aws ec2 help
$ aws ec2 describe-instances help
```
--- notes
รูปแบบบรรทัดคำสั่งแบ่งออกเป็นหลายส่วน แต่ละส่วนระบุการกระทำที่จะเกิดขึ้น
- ใช้คำสั่ง `aws` ซึ่งเป็นโครงสร้างพื้นฐานของการเรียกบรรทัดคำสั่ง AWS จากนั้นคุณพร้อมจะระบุการกระทำเพิ่มเติม
- ระบุบริการระดับบนสุดที่จะเรียก ตัวอย่างเช่น หากต้องการเรียก Amazon EC2 ให้ใส่คำสั่ง `ec2` ตามที่แสดงในแผนภาพ รายการบริการที่รองรับดูได้ที่ http://docs.aws.amazon.com/cli/latest/reference/
- ระบุการดำเนินการ (operation) ที่จะเรียก นี่คือการดำเนินการที่จะทำกับบริการที่ระบุในขั้นที่ 2 (Step #2) เช่น stop-instances หรือ run-instances ในตัวอย่างที่สองบนสไลด์ คำสั่งย่อย run-instances ถูกใช้เพื่อขอสร้าง Amazon EC2 instance ใหม่
- ระบุพารามิเตอร์ สามารถระบุพารามิเตอร์ได้หนึ่งตัวหรือมากกว่าขึ้นอยู่กับการดำเนินการที่เรียก พารามิเตอร์คืออาร์กิวเมนต์หรือรายละเอียดที่ใช้ในการดำเนินการ บางการดำเนินการมีพารามิเตอร์ที่จำเป็น ขณะที่บางการดำเนินการไม่ต้องใช้พารามิเตอร์ การดำเนินการส่วนใหญ่ยังมีพารามิเตอร์ทางเลือกให้ไม่กี่ตัวหรือหลายตัว ในตัวอย่างแรกบนสไลด์ การดำเนินการ stop-instances ต้องใช้พารามิเตอร์ instance-id (มิฉะนั้นจะไม่ชัดเจนว่าควรหยุด instance ใด)
- **หมายเหตุ (NOTE):** ชื่อพารามิเตอร์นำหน้าด้วยขีดสองตัว (--) ตัวอย่างเช่น ในการรันการดำเนินการ run-instances ของ Amazon EC2 จะต้องระบุพารามิเตอร์ที่จำเป็นหลายตัว และอาจมีพารามิเตอร์ทางเลือกบางตัว พารามิเตอร์ที่จำเป็นรวมถึง AMI ID ที่ใช้สร้าง instance
- สุดท้าย ระบุตัวเลือก (options) ตัวอย่างเช่น หลังจากเรียก `aws ec2 stop-instances` ให้ใช้ตัวเลือก `--output` เพื่อระบุรูปแบบของผลตอบกลับ

Description (คำอธิบาย): Amazon Elastic Compute Cloud (Amazon EC2) ให้ความสามารถในการประมวลผลที่ปรับขนาดได้บน AWS Cloud การใช้ Amazon EC2 ทำให้ไม่ต้องลงทุนฮาร์ดแวร์ล่วงหน้า คุณจึงพัฒนาและ deploy แอปพลิเคชันได้เร็วขึ้น
Available Commands (คำสั่งที่ใช้ได้):
- attach-volume
- copy-snapshot
- create-image
- delete-snapshot
- start-instances
- stop-instances
ไวยากรณ์เพิ่มเติมและรายการคำสั่งที่ใช้ได้ดูได้ในเอกสาร AWS CLI Command Reference: https://docs.aws.amazon.com/cli/latest/reference/index.html#cli-aws
