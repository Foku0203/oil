# โมดูล 8: พื้นที่จัดเก็บและการเก็บถาวร
Amazon Elastic File System

=== P032
# Amazon EFS
Amazon Elastic File System – พื้นที่จัดเก็บแบบระบบไฟล์สำหรับภาระงานบน Linux
- พื้นที่จัดเก็บไฟล์ที่ใช้ร่วมกัน (Shared file storage)
- ระบบไฟล์ระดับเพตะไบต์ (Petabyte-scale file system)
- รองรับโปรโตคอล Network File System เวอร์ชัน 4.0 และ 4.1
- เข้ากันได้กับ AMIs บน Linux ทั้งหมดสำหรับ Amazon EC2

=== P033
# การตั้งค่าระบบไฟล์ Amazon EFS
แผนภาพ: Region → VPC → Availability zone → Subnet: Instance ใช้ Network interface เชื่อมกับ Mount target (ซึ่งมี Network interface ของตัวเอง) → Amazon Elastic File System

=== P034
# กรณีการใช้งาน Amazon EFS
Amazon EFS ออกแบบมาให้มีสมรรถนะรองรับภาระงานและแอปพลิเคชันได้หลากหลาย:
- Home directories (โฟลเดอร์ส่วนตัวของผู้ใช้)
- ระบบไฟล์สำหรับแอปพลิเคชันขององค์กร
- การทดสอบและพัฒนาแอปพลิเคชัน
- การสำรองข้อมูลฐานข้อมูล
- การให้บริการเว็บและการจัดการเนื้อหา
- เวิร์กโฟลว์ด้านสื่อ (Media workflows)
- การวิเคราะห์ Big Data

=== P035
# คุณลักษณะด้านสมรรถนะของ Amazon EFS
- **โหมดสมรรถนะ (Performance modes):** General purpose, Max I/O
- **คลาสพื้นที่จัดเก็บ (Storage classes):** Standard, Infrequent access
- **โหมดปริมาณงาน (Throughput modes):** Bursting throughput, Provisioned throughput

=== P036
# ประเด็นสำคัญ (Key Takeaways)
- Amazon EFS เป็นบริการพื้นที่จัดเก็บแบบระบบไฟล์ที่มีผู้ดูแลให้เต็มรูปแบบ ซึ่งใช้โปรโตคอล NFS
- ใช้ Amazon EFS เพื่อรองรับภาระงานบน Linux ใน AWS หรือ on-premises ที่ต้องการพื้นที่จัดเก็บแบบระบบไฟล์ที่ใช้ร่วมกัน
- สมรรถนะของระบบไฟล์ Amazon EFS ควบคุมได้ผ่านคุณลักษณะด้านสมรรถนะ

=== P037
# โมดูล 8: พื้นที่จัดเก็บและการเก็บถาวร
Amazon S3

=== P038
# Amazon S3
- เข้าถึงออบเจกต์ด้วยคีย์ได้อย่างรวดเร็ว ทนทาน และพร้อมใช้งานสูง
- พื้นที่จัดเก็บแบบออบเจกต์ที่สร้างมาเพื่อจัดเก็บและดึงข้อมูล
- ไม่ใช่ระบบไฟล์
แผนภาพ: Client → CLI ส่งคำขอ GET ผ่าน S3 API → Amazon S3 Bucket → ส่งออบเจกต์กลับมา (Object returned)

=== P039
# ลักษณะของ Amazon S3
ลักษณะของ Amazon S3 ได้แก่:
- เข้าถึงได้จากทุกที่ (ทั้งภายในและภายนอก AWS)
- ทนทานสูง (ออกแบบให้มีความทนทาน 99.999999999%) ด้วยการจัดเก็บซ้ำซ้อน
- พร้อมใช้งานสูง (ออกแบบให้มีความพร้อมใช้งาน 99.99%)
- ไม่จำกัดปริมาณข้อมูลที่จัดเก็บ
- สูงสุด 5 TB ต่อออบเจกต์

=== P040
# การกำหนดเวอร์ชันของ Amazon S3 (versioning)
Amazon S3 versioning ปกป้องออบเจกต์จากการเขียนทับและการลบโดยไม่ตั้งใจ
| การกระทำ (Action) | เปิด Versioning (Enabled) | ปิด Versioning / ระงับ Versioning (Disabled / Suspended) |
| อัปโหลดออบเจกต์ด้วย Key เดิม | สร้างออบเจกต์ใหม่ที่มี version ID ต่างกัน ทั้งสองดึงได้ด้วย version ID | เขียนทับออบเจกต์เดิม และดึงออบเจกต์ก่อนหน้าไม่ได้อีก |
| ลบ (Delete) | เพิ่ม Delete marker แต่ยังดึงออบเจกต์ได้ด้วย version ID | ลบออบเจกต์ และดึงไม่ได้อีก |

=== P041
# คลาสพื้นที่จัดเก็บของออบเจกต์ (Object storage classes)
- **ใช้งานทั่วไป (General purpose):** Amazon S3 Standard
- **จัดลำดับชั้นอัจฉริยะ (Intelligent tiering):** Amazon S3 Intelligent-Tiering
- **เข้าถึงไม่บ่อย (Infrequent access):** Amazon S3 Standard-Infrequent Access (S3 Standard-IA), Amazon S3 One Zone-Infrequent Access (S3 One Zone-IA)
- **เก็บถาวร (Archive):** Amazon S3 Glacier, Amazon S3 – Glacier Deep Archive

=== P042
# Intelligent tiering
Intelligent tiering ย้ายข้อมูลไปยังชั้นการเข้าถึง (access tier) ที่คุ้มค่าที่สุดโดยอัตโนมัติ
- เฝ้าติดตามรูปแบบการเข้าถึงออบเจกต์
- ย้ายออบเจกต์ระหว่างชั้นเข้าถึงบ่อย (Frequent access) และชั้นเข้าถึงไม่บ่อย (Infrequent access)
- เข้ารหัสข้อมูลทั้งระหว่างส่ง (in transit) และขณะจัดเก็บ (at rest)
- ไม่กระทบสมรรถนะและไม่เพิ่มภาระการปฏิบัติงาน

=== P043
# การบล็อกการเข้าถึงแบบสาธารณะของ Amazon S3 (block public access)
(ภาพหน้าจอคอนโซล S3 แท็บ Permissions → Public access settings: "Public access settings for this bucket – ใช้การตั้งค่า Amazon S3 block public access เพื่อบังคับไม่ให้ buckets เปิดให้เข้าถึงข้อมูลแบบสาธารณะ คุณยังตั้งค่า block public access ที่ระดับบัญชีได้ด้วย" มีตัวเลือก:
- Manage public access control lists (ACLs): Block new public ACLs and uploading public objects (แนะนำ) = True; Remove public access granted through public ACLs (แนะนำ) = True
- Manage public bucket policies: Block new public bucket policies (แนะนำ) = True; Block public and cross-account access if bucket has public policies (แนะนำ) = True)

=== P044
# การตั้งค่าการเข้าถึงแบบสาธารณะของ Amazon S3
- บล็อก public ACLs ใหม่และการอัปโหลดออบเจกต์แบบสาธารณะ
- ลบการเข้าถึงแบบสาธารณะที่ให้ไว้ผ่าน public ACLs
- บล็อก public bucket policies ใหม่
- บล็อกการเข้าถึงแบบสาธารณะและข้ามบัญชีไปยัง buckets ที่มี public policies

=== P045
# Amazon S3 object lock
- จัดเก็บออบเจกต์ด้วยโมเดล “เขียนครั้งเดียว อ่านได้หลายครั้ง” (write once, read many – WORM)
- เปิดใช้ตอนสร้าง bucket
**สองวิธีในการจัดการการเก็บรักษาออบเจกต์:**
- Retention (ระยะเวลาเก็บรักษา)
- Legal hold (การระงับทางกฎหมาย)
**สองโหมดการเก็บรักษา:**
- Compliance
- Governance

=== P046
# การแจ้งเตือนเหตุการณ์ของ Amazon S3 (Event notification)
ตั้งค่า buckets ให้ส่งการแจ้งเตือนเมื่อออบเจกต์ถูก:
- เพิ่ม (Added)
- ลบ (Deleted)
- เขียนทับ (Overwritten)
ส่งการแจ้งเตือนได้โดยตรงไปยัง:
- Amazon SQS queues
- Amazon SNS topics
- AWS Lambda functions
แผนภาพ (Region): ออบเจกต์ขาเข้า (Incoming Objects) → Amazon S3 Bucket → ส่ง Message ไปยัง Queue, ส่ง Message ไปยัง Topic และเรียกใช้ (Invocation) Lambda function

=== P047
# คุณสมบัติเพิ่มเติมของ Amazon S3
| คุณสมบัติ (Feature) | วัตถุประสงค์/ประโยชน์ | วิธีใช้ (How to use it) |
| การจัดการวงจรชีวิตของออบเจกต์ (Object lifecycle management) | จัดการออบเจกต์ให้จัดเก็บอย่างคุ้มค่าตลอดวงจรชีวิต | สร้าง lifecycle configuration ที่มีกฎกำหนดว่า**เมื่อใดออบเจกต์ควรย้ายไปยังคลาสพื้นที่จัดเก็บอื่น**และ**เมื่อใดควรถูกลบ** |
| Presigned object URL | แชร์ออบเจกต์ส่วนตัวกับผู้ที่ไม่มี AWS security credentials หรือสิทธิ์ | สร้าง presigned object URL ผ่านโปรแกรม แล้วให้ผู้รับใช้เข้าถึงออบเจกต์ |
| Cross-Origin Resource Sharing (CORS) | ให้ Amazon S3 bucket ที่โฮสต์เว็บไซต์แบบสแตติกรองรับ CORS; หลาย origin เข้าถึง bucket เดียว (Many origins to one bucket) | สร้าง CORS configuration บน bucket ที่มีกฎระบุ origins ที่ได้รับอนุญาตและการดำเนินการ HTTP |

=== P048
# สร้างและแสดงรายการ Amazon S3 buckets
- สร้าง bucket ใหม่:
```
aws s3 mb s3://mybucket
```
- แสดงรายการ buckets ทั้งหมดในบัญชี AWS:
```
aws s3 ls
```

=== P049
# ทำงานกับ Amazon S3 objects
- คัดลอกไฟล์ในเครื่องขึ้น Amazon S3:
```
$ aws s3 cp file.txt s3://mybucket/myprefix/file.txt
```
- ซิงก์ออบเจกต์ภายใต้ bucket และ prefix ที่ระบุมายังไดเรกทอรีปัจจุบันในเครื่อง:
```
$ aws s3 sync s3://mybucket/myprefix/
```
- ลบออบเจกต์ออกจาก bucket:
```
$ aws s3 rm s3://mybucket/myprefix/file.txt
```

=== P050
# สร้างออบเจกต์ด้วยคลาสพื้นที่จัดเก็บที่ระบุ
ใช้พารามิเตอร์ `–-storage-class` กับคำสั่ง copy เพื่อระบุคลาสพื้นที่จัดเก็บ
```
$ aws s3 cp file.txt s3://mybucket/myprefix/file.txt \
--storage-class INTELLIGENT_TIERING
```

=== P051
# คำสั่ง s3api
คำสั่ง s3api:
- ให้การเข้าถึง Amazon S3 APIs โดยตรง
- ทำการดำเนินการที่ `aws s3` ไม่มีให้ได้
ตัวอย่าง `aws s3api`:
- create-multipart-upload
- put-object-acl
- put-bucket-policy
- list-object-versions

=== P052
# ประเด็นสำคัญ (Key Takeaways)
- Amazon S3 เป็นบริการพื้นที่จัดเก็บแบบออบเจกต์ที่จัดเตรียมระดับ Region
- ใช้ Amazon S3 เพื่อความทนทานและความพร้อมใช้งานสูง
- Amazon S3 มีคลาสพื้นที่จัดเก็บหลายแบบ versioning, object locking และ event notification

Amazon S3 Glacier

=== P054
# Amazon S3 Glacier
- การเก็บถาวรข้อมูลและการสำรองข้อมูลระยะยาวด้วยต้นทุนต่ำมาก
- ดึงข้อมูลตามคำขอ (Retrieval by request)
- ตั้งค่าให้เก็บถาวรเนื้อหาใน Amazon S3 ไปยัง Amazon S3 Glacier ตาม lifecycle ได้
แผนภาพ: ข้อมูลเข้าสู่ Amazon S3 Glacier ได้จาก Instance (เก็บถาวรผ่าน API – Archive via API), On-premises server (เก็บถาวรผ่าน AWS CLI) หรือ… Amazon Simple Storage Service (S3) (ใช้ lifecycle rules)

=== P055
# Amazon S3 Glacier จัดเก็บข้อมูลอย่างไร
- Amazon S3 Glacier จัดเก็บข้อมูลใน archive
  - archive คือหน่วยข้อมูลพื้นฐานใน Amazon Glacier (เอกสาร วิดีโอ รูปภาพ ฯลฯ)
- vault คือกลุ่มของ archives
แผนภาพ: API application → Vault: https://glacier.us-east-1.amazonaws.com/111122223333/vaults/examplevault → Archive: $VAULT_URL/archives/<archive_id>

=== P056
# การทำงานกับ Amazon S3 Glacier
ทำงานกับ Amazon S3 Glacier ได้ผ่าน:
**Amazon S3 lifecycle policies**
- เข้าถึงไฟล์ที่เก็บถาวรผ่านคอนโซล Amazon S3 หรือ Amazon S3 API
**Amazon S3 Glacier API**
- เพิ่มไฟล์โดยตรง
- ในการดึงไฟล์:
  - 1. เริ่มคำของาน (job request)
  - 2. เลือกการดำเนินการดึง archive (archive retrieval)
  - 3. (ไม่บังคับ) ระบุตัวกรองช่วงวันที่หรือช่วงไบต์
  - 4. ตรวจสอบเป็นระยะว่างานเสร็จหรือยัง (poll) หรือรับการแจ้งเตือนผ่าน SNS

=== P057
# ตัวเลือกการดึง archive (Archive retrieval options)
| ตัวเลือก | ระยะเวลา |
| Expedited (เร่งด่วน) | 1-5 นาที |
| Standard (มาตรฐาน) | 3-5 ชั่วโมง |
| Bulk (ปริมาณมาก) | 5-12 ชั่วโมง |

=== P058
# ประเด็นสำคัญ (Key Takeaways)
- Amazon S3 Glacier เป็นบริการจัดเก็บระยะยาวสำหรับเนื้อหาที่ไม่จำเป็นต้องพร้อมใช้งานทันที
- ใช้ Amazon S3 Glacier เป็นโซลูชันจัดเก็บระยะยาวราคาประหยัดสำหรับการเก็บถาวรหรือสำรองข้อมูล
- Amazon S3 Glacier มีตัวเลือกการดึง archive สามแบบ

# AWS Storage Gateway
AWS Storage Gateway – โซลูชันพื้นที่จัดเก็บแบบไฮบริดคลาวด์ที่ให้แอปพลิเคชัน on-premises เข้าถึงข้อมูลใน AWS Cloud ได้

- Volume gateway
- Tape gateway
