=== P033
# Database Migration Service (AWS DMS)
- AWS Database Migration Service (AWS DMS) ร่วมกับ AWS Schema Conversion Tool (AWS SCT) ช่วยให้คุณย้ายฐานข้อมูลมายัง AWS โดยมีช่วงหยุดทำงานน้อยที่สุด
- รองรับฐานข้อมูลเชิงพาณิชย์และโอเพนซอร์สที่ใช้กันแพร่หลายส่วนใหญ่
- ทำให้แอปพลิเคชันยังทำงานได้ระหว่างการย้าย
(ภาพ AWS Database Migration Service เชื่อมฐานข้อมูลต้นทาง เช่น MariaDB, Oracle, PostgreSQL, Microsoft SQL Server, MongoDB, SAP ASE, Azure SQL กับปลายทาง Amazon Simple Storage Service (S3), Amazon Redshift, Amazon DynamoDB, Amazon Aurora)

=== P034
# AWS DMS endpoints
การจับคู่ต้นทาง/ปลายทางของ DMS (DMS Source/Target Combinations):
| ต้นทาง / ปลายทาง | On Premises | Amazon RDS, Redshift, Amazon S3 และ DynamoDB | Amazon EC2 |
| On Premises | ไม่รองรับ (Not supported) | รองรับ (Supported) | รองรับ (Supported) |
| Amazon RDS และ Amazon S3 | รองรับ (Supported) | รองรับ (Supported) | รองรับ (Supported) |
| Amazon EC2 | รองรับ (Supported) | รองรับ (Supported) | รองรับ (Supported) |
| Azure SQL | ไม่รองรับ (Not supported) | รองรับ (Supported) | รองรับ (Supported) |

=== P035
# สถาปัตยกรรมของ AWS DMS
แผนภาพ: ต้นทาง (SOURCE) → Replication instance ใน VPC ที่รัน Task → ปลายทาง (TARGET)
- ต้นทางเป็นได้: ฐานข้อมูล on-premises (On-premises database), RDS DB instance, DB บน EC2 instance
- ปลายทางเป็นได้: ฐานข้อมูล on-premises, RDS DB instance, DB บน EC2 instance

=== P038
# สรุปกระบวนการย้ายฐานข้อมูล
- **Step 1:** schema ของฐานข้อมูลต้นทาง → AWS Schema Conversion Tool (AWS SCT) → schema ของฐานข้อมูลปลายทาง
- **Step 2:** ข้อมูลของฐานข้อมูลต้นทาง → AWS Database Migration Service (AWS DMS) → ข้อมูลของฐานข้อมูลปลายทาง
