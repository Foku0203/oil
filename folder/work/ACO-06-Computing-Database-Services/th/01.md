| การขยายขนาด (Scalability) | แนวตั้ง (Vertical) | แนวนอน (Horizontal) |

Amazon Relational Database Service (Amazon RDS)

=== P013
# Amazon RDS DB instances
- **DB Instance Class:** CPU, หน่วยความจำ (Memory), สมรรถนะเครือข่าย (Network Performance)
- **DB Instance Storage:** Magnetic, General Purpose (SSD), Provisioned IOPS
- **DB Engines:**
  - Amazon Aurora
  - MySQL
  - SQL Server
  - PostgreSQL
  - MariaDB
  - Oracle

=== P014
# การสำรองข้อมูลของ Amazon RDS (Amazon RDS backup)
ตัวเลือกการสำรองข้อมูลของ Amazon RDS ได้แก่:
**อัตโนมัติ (Automatic):**
- สร้างการสำรองข้อมูลอัตโนมัติ (snapshot เต็มรายวันและ transaction logs) ของ DB instance ระหว่างช่วงเวลาสำรองข้อมูล (backup window)
**ด้วยตนเอง (Manual):**
- สร้าง snapshot ของ storage volume ของ DB instance

=== P015
# สร้าง snapshots: คำสั่ง
คำสั่งสำหรับสร้าง snapshot คือ:
```
$ aws rds create-db-snapshot --db-instance-identifier mytestdb --db-snapshot-identifier mydbsnapshot
```

=== P016
# กู้คืน DB จาก snapshot: คำสั่ง
คำสั่งสำหรับกู้คืน DB จาก snapshot คือ:
```
$ aws rds restore-db-instance-from-db-snapshot --db-instance-identifier mytestdb-new --db-snapshot-identifier mydbsnapshot
```
(ต้นฉบับพิมพ์ว่า "restore a SB" ซึ่งหมายถึง DB)

=== P017
# คัดลอก RDS Snapshot: คำสั่ง
คำสั่งสำหรับคัดลอก RDS snapshot คือ:
```
$ aws rds copy-db-snapshot --source-db-snapshot-identifier mydbsnapshot --target-db-snapshot-identifier mydbsnapshotcopy --copy-tags
```

=== P018
# ลบ snapshot: คำสั่ง
คำสั่งสำหรับลบ snapshot คือ:
```
$ aws rds delete-db-snapshot --db-snapshot-identifier mydbsnapshot
```

=== P019
# ความพร้อมใช้งานสูงด้วยการ deploy แบบ multi-AZ: การจำลองข้อมูล (Replication)
แผนภาพ (VPC):
- Availability Zone 1: Public subnet มี Amazon EC2 instance (App); Private subnet มี RDS DB primary instance
- Availability Zone 2: Public subnet มี Amazon EC2 instance (App); Private subnet มี RDS DB standby instance
- primary instance จำลองข้อมูลแบบซิงโครนัส (Synchronous replication) ไปยัง standby instance

=== P020
# ความพร้อมใช้งานสูงด้วยการ deploy แบบ multi-AZ: การสลับไปใช้ระบบสำรอง (Failover)
แผนภาพ (VPC):
- Availability Zone 1: Public subnet มี Amazon EC2 instance (App); Private subnet มี RDS DB primary instance
- Availability Zone 2: Public subnet มี Amazon EC2 instance (App); Private subnet มี RDS DB standby instance
- เมื่อ primary ล้มเหลว จะเกิด Failover ไปยัง RDS DB standby instance

=== P021
# การขยายขนาด Amazon RDS (Amazon RDS scaling)
แผนภาพ (VPC → Availability Zone): App บน Amazon EC2 instance ใน Public subnet อ่าน/เขียน (Read/write) ที่ RDS DB primary instance และอ่าน (Read) จาก RDS DB read replica instance ใน Private subnet; primary จำลองข้อมูลแบบอะซิงโครนัส (Asynchronous replication) ไปยัง read replica
การขยายขนาด Amazon RDS:
- Instance class
  - เปลี่ยน instance class เพื่อเพิ่มความสามารถด้านการประมวลผลและหน่วยความจำ
- ความจุพื้นที่จัดเก็บ (Storage capacity)
  - ขยายพื้นที่จัดเก็บของ instances ที่มีอยู่
- ภาระงานด้านการอ่านสามารถใช้ read replicas ได้

# ประเด็นสำคัญ (Key Takeaways)
- Amazon RDS รองรับ database engines หลายตัวทั้งแบบโอเพนซอร์สและเชิงพาณิชย์
- instance class ของ Amazon RDS ให้คุณเลือกประเภท instance (การประมวลผล) ส่วน storage type ช่วยกำหนดประเภทพื้นที่จัดเก็บ ขนาด และ IOPS ของ DB
- RDS Standby และ read replicas ช่วยเพิ่มความพร้อมใช้งานและความทนทานให้ DB Instances
- การสำรองข้อมูลอัตโนมัติและ snapshot ด้วยตนเองเป็นวิธีสำรองและกู้คืน DB ของคุณ

=== P025
# ประโยชน์ของ Amazon Aurora
ประโยชน์ของ Amazon Aurora ได้แก่:
- รวดเร็วและพร้อมใช้งาน (Fast and available)
- บริการแบบมีผู้ดูแลให้ (Managed service)
- ใช้งานง่าย (Simple)
- จ่ายตามการใช้งาน (Pay-as-you-go)
- เข้ากันได้ (Compatible)
รายละเอียด:
- ฐานข้อมูลเชิงสัมพันธ์ที่เข้ากันได้กับ MySQL และ PostgreSQL
- ผสานสมรรถนะและความพร้อมใช้งานของฐานข้อมูลเชิงพาณิชย์ระดับสูง
- ความเรียบง่ายและความคุ้มค่าของฐานข้อมูลโอเพนซอร์ส

=== P026
# สถาปัตยกรรมความพร้อมใช้งานสูงของ Amazon Aurora
แผนภาพ Amazon Aurora DB Cluster:
- Availability Zone 1: Amazon Aurora primary instance – รับการเขียน (Writes) และการอ่าน (Reads)
- Availability Zone 2: Amazon Aurora replica – รับการอ่าน (Reads)
- Availability Zone 3: Amazon Aurora replicas – รับการอ่าน (Reads)
- ทุก AZ ใช้ Cluster volume ร่วมกัน ซึ่งเก็บสำเนาข้อมูล (Data copies) ไว้ในทุก AZ

=== P027
# โมดูล 6: การประมวลผล (บริการฐานข้อมูล)
Amazon DynamoDB

=== P028
# ประโยชน์ของ Amazon DynamoDB
Amazon DynamoDB เป็นบริการฐานข้อมูลแบบไม่สัมพันธ์ (non-relational) ที่รวดเร็วและขยายขนาดได้สูง
ประโยชน์ของ Amazon DynamoDB ได้แก่:
- มีผู้ดูแลให้เต็มรูปแบบ (Fully managed)
- query ที่มีความหน่วงต่ำ (Low-latency queries)
- การควบคุมการเข้าถึงแบบละเอียด (Fine-grained access control)
- ความยืดหยุ่น (Flexibility)

=== P029
# โมเดลข้อมูลของ Amazon DynamoDB
- ตาราง (Table) = ชุดของ items
- Item = ชุดของ attributes
- Attributes เก็บองค์ประกอบของข้อมูล
- ข้อมูลถูกแบ่งพาร์ทิชันตาม partition key (เช่น Partition Key: A, B, C, D)
- ตัวอย่างคีย์: User ID เป็น Partition key และ Order ID เป็น Sort key
