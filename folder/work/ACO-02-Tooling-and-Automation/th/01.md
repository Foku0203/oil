# ภาพรวมของ AWS Systems Manager
แผนภาพ: AWS Systems Manager → Amazon Elastic Compute Cloud (Amazon EC2) instances โดยทำงานด้าน:
- Software inventory (รายการซอฟต์แวร์)
- OS patches (แพตช์ระบบปฏิบัติการ)
- System images (อิมเมจของระบบ)
- OS management and configuration (การจัดการและตั้งค่าระบบปฏิบัติการ)
**คุณสมบัติ (Features):**
- Automation
- Run Command
- Session Manager
- Patch Manager
- Maintenance Windows
- State Manager
- Parameter Store
- Inventory
- Insights dashboard
--- notes
AWS Systems Manager เป็นบริการจัดการที่ช่วยให้ผู้ใช้:
- รวบรวมรายการซอฟต์แวร์ (software inventory)
- ติดตั้งแพตช์ระบบปฏิบัติการ (OS patches)
- สร้างอิมเมจของระบบ (system images)
- ตั้งค่าระบบปฏิบัติการ Windows และ Linux
AWS Systems Manager ถูกออกแบบให้เน้นระบบอัตโนมัติอย่างมาก ซึ่งช่วยให้ตั้งค่าและจัดการระบบที่รันอยู่ใน on-premises หรือบน AWS ได้ AWS Systems Manager ให้ผู้ใช้เลือก instances ที่ต้องการจัดการ และกำหนดงานจัดการที่ต้องการทำ
AWS Systems Manager มีคุณสมบัติและประโยชน์มากมายที่ผู้เชี่ยวชาญด้านการปฏิบัติการระบบน่าจะพบว่ามีประโยชน์
ตัวอย่างเช่น คุณสมบัติ Run Command ให้คุณรันสคริปต์และโปรแกรมจากระยะไกล ขณะที่ State Manager ทำให้มั่นใจว่า EC2 instances ของคุณถูก bootstrap ด้วยซอฟต์แวร์ที่กำหนดตอนเริ่มทำงาน คุณใช้ Inventory Manager เพื่อรวบรวมและ query ข้อมูลเกี่ยวกับการตั้งค่าและรายการของ EC2 instances และซอฟต์แวร์ที่ติดตั้งอยู่ และด้วย Maintenance Window คุณสามารถกำหนดช่วงเวลาที่เกิดซ้ำเพื่อรันงานดูแลระบบและงานบำรุงรักษากับ instances ของคุณ

=== S009
# AWS Systems Manager: Automation
ทำให้งานปฏิบัติการไอทีและงานจัดการที่พบบ่อยและทำซ้ำ ๆ บนทรัพยากร AWS เป็นอัตโนมัติอย่างปลอดภัย
- #1 สร้าง automation document
- #2 รัน automation document
- #3 เฝ้าติดตามและทดสอบ automation
--- notes
คุณสมบัติ Automation ใน Systems Manager สามารถกำหนดงานไอทีทั่วไปเป็นชุดของขั้นตอนใน AWS Systems Manager document (SSM document) จากนั้นคุณสมบัติ Automation จะรันทุกขั้นตอนในเอกสารกับทรัพยากร AWS ทั้งกลุ่ม ตัวอย่างเช่น คุณสามารถกำหนด automation เพื่อแก้ไข instances ที่ติดต่อไม่ได้ สร้าง golden Amazon Machine Images (AMI) (AMIs) หรือติดตั้งแพตช์ให้ instances นอกจากนี้ยังเขียน automation แบบกำหนดเองด้วย JavaScript Object Notation (JSON) ได้ และสามารถตั้งค่า Amazon CloudWatch Events ให้ทริกเกอร์ Systems Manager automations ได้ด้วย
แนวทางที่แนะนำในการพัฒนาและทดสอบ Systems Manager automation คือ:
- สร้าง automation document หรือใช้ automation template ที่มีอยู่ ซึ่งมีขั้นตอนตามลำดับและพารามิเตอร์ที่ Systems Manager จะรัน
- รัน automation ด้วย Systems Manager ซึ่งจะทำสิ่งต่าง ๆ เช่น:
  - launch instance
  - ถ่าย snapshot
  - ติด tag ให้ instances
  - ลบอิมเมจเก่า
  - terminate instance
- เฝ้าติดตามขั้นตอนการทำงานของ automation (เช่น ใช้ AWS Management Console) หลังจาก automation เสร็จ ให้ยืนยันว่าได้ผลลัพธ์ตามที่คาดไว้ ตัวอย่างเช่น คุณอาจ launch instance ทดสอบจาก Amazon Machine Image (AMI) ที่ถูกอัปเดตโดย Systems Manager automation เพื่อตรวจสอบว่ามีคุณลักษณะตามที่คาดไว้

=== S010
# AWS Systems Manager: Run command
(ภาพ: ตัวอย่างประเภทคำสั่งที่ Amazon เตรียมไว้ให้ – Example command types provided by Amazon)
**Run Command:**
- ใช้คำสั่งที่กำหนดไว้ล่วงหน้า หรือสร้างคำสั่งของคุณเอง
- เลือก instances หรือ tags
- เลือกการควบคุม (controls) หรือกำหนดเวลา (schedules)
- รันคำสั่ง
--- notes
Systems Manager Run Command เป็นวิธีง่าย ๆ ในการรันคำสั่งที่กำหนดไว้ล่วงหน้ากับ EC2 instances คำสั่งที่รันด้วย Run Command ช่วยลดภาระการจัดการ เพราะผู้ใช้จัดการ instances ได้โดยไม่ต้องตั้ง bastion hosts หรือจัดการ Secure Shell (SSH) keys และใบรับรอง
ด้วยการผสานรวมกับ AWS Identity and Access Management (IAM) คุณสามารถกำหนดสิทธิ์แบบละเอียดเพื่อควบคุมการกระทำที่ผู้ใช้ทำกับ instances ได้ ทุกการกระทำที่ทำด้วย Systems Manager ยังสามารถบันทึกได้โดย AWS CloudTrail ซึ่งช่วยให้ผู้ใช้ตรวจสอบ (audit) การเปลี่ยนแปลงทั่วทั้งสภาพแวดล้อมได้

=== S011
# AWS Systems Manager: Session Manager
เชื่อมต่อกับ instances อย่างปลอดภัยโดยไม่ต้องเปิด inbound ports ไม่ต้องใช้ bastion hosts และไม่ต้องดูแล SSH keys
แผนภาพ:
- ผู้ใช้ (User) → AWS Systems Manager → secure session → EC2 instance (Windows หรือ Linux)
- ผู้ใช้ → Command Line interface (`aws start-session --target`) → secure session → EC2 instance (Windows หรือ Linux)
- การบันทึก session (Session logging) → Amazon CloudWatch Logs และ Amazon S3 Bucket
--- notes
คุณสมบัติ Session Manager ใน AWS Systems Manager ช่วยให้ผู้ใช้จัดการ EC2 instances ผ่าน shell แบบโต้ตอบบนเบราว์เซอร์ ที่เข้าถึงได้ใน AWS Management Console
Session Manager ให้การจัดการ instance ที่ปลอดภัยและตรวจสอบได้ โดยไม่ต้องเปิด inbound ports ใน security groups ไม่ต้องดูแล bastion host instances ใน EC2 subnets และไม่ต้องจัดการ SSH keys
Session Manager ยังทำให้ปฏิบัติตามนโยบายองค์กรได้ตรงไปตรงมา ซึ่งนโยบายเหล่านั้นกำหนดให้ต้องควบคุมการเข้าถึง instances มีแนวปฏิบัติด้านความปลอดภัยที่เข้มงวด และมี log ที่ตรวจสอบได้ซึ่งมีรายละเอียดการเข้าถึง instance ผู้ใช้ได้ประโยชน์เหล่านี้ขณะที่ยังเปิดให้ผู้ใช้ปลายทางเข้าถึง EC2 instances ได้

=== S012
# AWS Systems Manager: Patch Manager
deploy แพตช์ของระบบปฏิบัติการและซอฟต์แวร์โดยอัตโนมัติให้กับ Amazon EC2 หรือ on-premises instances กลุ่มใหญ่
- 1. สร้าง baseline
- 2. สร้าง maintenance window สำหรับการติดตั้งแพตช์
- 3. ติดตั้ง (apply) และรีบูต
- 4. ตรวจสอบ (audit) ผลลัพธ์ด้วยการตรวจความสอดคล้อง (compliance)
--- notes
การติดตั้งแพตช์ให้เซิร์ฟเวอร์และ instances มีความท้าทายหลายประการ ได้แก่:
- เวลาที่ใช้ในการติดตั้งแพตช์ให้ EC2 instances หรือเครื่อง on-premises หลายเครื่อง
- ลักษณะงานที่ต้องทำซ้ำ ๆ
- ข้อผิดพลาดที่อาจทำให้ระบบหยุดทำงาน (downtime)
- ปัญหาด้านการปฏิบัติตามข้อกำหนด (compliance)
ในการใช้ Systems Manager Patch Manager เพื่อทำให้การติดตั้งแพตช์เป็นอัตโนมัติ:
- สร้าง patch baseline ซึ่งมีกฎที่อนุมัติหรือปฏิเสธแพตช์โดยอัตโนมัติ
- กำหนด maintenance window และจัดกลุ่ม instances เข้าด้วยกันเพื่อติดตั้งแพตช์
- ติดตั้งแพตช์ใน maintenance window และรีบูตทุก instance ใน patch group
- ทบทวนผลลัพธ์และรายละเอียดของ patch compliance

=== S013
# AWS Systems Manager: Maintenance Windows
กำหนดช่วงเวลาเพื่อรันงานดูแลระบบและงานบำรุงรักษากับ instances ของคุณ
- #1 สร้าง Maintenance Window
- #2 กำหนดเป้าหมาย (Assign targets)
- #3 กำหนดงาน (Assign tasks)
- #4 ทบทวนสถานะหลังงานเสร็จสิ้น
--- notes
คุณสมบัติ Maintenance Windows ของ Systems Manager ช่วยให้ผู้ใช้กำหนดเวลางานประจำ เช่น การติดตั้งแพตช์ ให้รันโดยอัตโนมัติ ผู้ใช้สามารถกำหนดขีดจำกัดจำนวนงานที่รันพร้อมกันและอัตราข้อผิดพลาดที่ยอมรับได้
ขั้นตอนการใช้ Maintenance Window คือ:
- สร้าง Maintenance Window
- กำหนดเป้าหมาย (targets)
- กำหนดงานที่จะรันกับเป้าหมายเหล่านั้น ประเภทงานที่รันได้ ได้แก่:
  - คำสั่งที่รันโดย Systems Manager Run Command
  - Systems Manager Automation workflows
  - AWS Step Function workflows
  - AWS Lambda functions
- ทบทวนสถานะของงานหลังจากรันงานเสร็จสิ้น

=== S014
# AWS Systems Manager: State Manager
รักษาการตั้งค่า (configuration) ของ Amazon EC2 หรือ on-premises instances ให้สม่ำเสมอ
วงจรการทำงาน:
- เลือก SSM document ที่กำหนดไว้ล่วงหน้า หรือสร้างขึ้นเอง
- ผูก (associate) instances ของคุณเข้ากับ document
- กำหนดตารางเวลา (schedule) สำหรับสถานะ (state)
- ส่งข้อมูลผลลัพธ์ไปยัง Amazon S3 (ไม่บังคับ)
--- notes
AWS Systems Manager State Manager เป็นบริการจัดการการตั้งค่า (configuration management) ที่ปลอดภัยและขยายขนาดได้ ซึ่งทำให้กระบวนการรักษา EC2 และโครงสร้างพื้นฐานแบบไฮบริดของคุณให้อยู่ในสถานะที่คุณกำหนดเป็นอัตโนมัติ
คุณสามารถติดตั้งซอฟต์แวร์เมื่อสร้าง EC2 instances, ดาวน์โหลดและอัปเดต agents, ตั้งค่าเครือข่าย, เข้าร่วม Windows domain, ติดตั้งแพตช์อัปเดตซอฟต์แวร์ให้ instances และรันสคริปต์บน managed instances ที่เป็น Linux และ Windows
State Manager ทำงานดังนี้:
- ขั้นแรก สร้าง AWS Systems Manager (SSM) document หรือระบุ document ที่มีอยู่ ซึ่งกำหนดการกระทำที่ Systems Manager จะทำกับ managed instances ของคุณ documents เขียนด้วย JavaScript Object Notation (JSON) หรือ YAML Ain’t Markup Language (YAML) และประกอบด้วยขั้นตอนและพารามิเตอร์ที่คุณระบุ
- จากนั้น ผูก managed instances ของคุณเข้ากับ SSM document เมื่อสร้างการผูก (association) คุณจะกำหนดตารางเวลาว่าจะใช้สถานะที่ตั้งค่าไว้บ่อยแค่ไหน สุดท้าย คุณสามารถเลือกเขียนผลลัพธ์ของคำสั่งลงใน Amazon Simple Storage Service (Amazon S3) bucket ได้เมื่อสร้าง association
