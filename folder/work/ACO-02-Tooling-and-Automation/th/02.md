# AWS Systems Manager: Parameter Store
ตาราง Parameter Store ในภาพ (เข้ารหัสด้วย AWS Key Management Service):
| ชื่อพารามิเตอร์ที่ไม่ซ้ำกัน (Unique Parameter Name) | รหัสผ่าน (Password) |
| /Dev/DB/UserName | DE24xd0w |
SSM document ที่อ้างอิงพารามิเตอร์นี้:
```
{
"schemaVersion": "2.2",
"description": "Sample schema version 2.2 document v3.",
"parameters": {
"dbname": {
"type": "String",
"default": "{{ssm:/Dev/DB/UserName}}"
}
},
"mainSteps": [{
"action": "aws:runShellScript",
"name": "runShellScript",
"inputs": {
"runCommand": ["echo DBUserName: {{ dbname }}"]
}
}]
}
```
--- notes
แทนที่จะเก็บข้อมูลที่ละเอียดอ่อนไว้ในไฟล์การตั้งค่าหรือเขียนตายตัว (hard code) ไว้ในซอร์สโค้ด คุณสามารถใช้ Systems Manager Parameter Store เก็บพารามิเตอร์เหล่านี้ แล้วอ้างอิงข้อมูลนี้ในแอปพลิเคชันหรือสคริปต์ ใช้ Parameter Store เก็บข้อมูลการตั้งค่า เช่น:
- รหัสผ่าน
- คีย์
- รหัสใบอนุญาต (license codes)
- สตริงเชื่อมต่อฐานข้อมูล (database strings)
ในตัวอย่างบนสไลด์ มีการสร้างพารามิเตอร์ใหม่เพื่อเก็บรหัสผ่าน จากนั้นชื่อพารามิเตอร์ถูกอ้างอิงในโค้ดที่แสดงทางขวา Parameter Store ผสานรวมกับ IAM เพื่อควบคุมการเข้าถึงพารามิเตอร์ และข้อมูลที่เก็บไว้สามารถเข้ารหัสด้วย AWS Key Management Service (AWS KMS)
ปัจจุบัน SSM documents ยังไม่รองรับการอ้างอิงพารามิเตอร์แบบ SecureString หมายความว่าหากจะใช้พารามิเตอร์ SecureString กับ (ตัวอย่างเช่น) Run Command จำเป็นต้องดึงค่าพารามิเตอร์ออกมาก่อน แล้วจึงส่งให้ Run Command

=== S016
# AWS Systems Manager: Inventory
รวบรวมข้อมูลเกี่ยวกับ instances และซอฟต์แวร์ที่ติดตั้งอยู่บน instances
ข้อมูลที่รวบรวม:
- Application data (ข้อมูลแอปพลิเคชัน)
- Files (ไฟล์)
- Network configurations (การตั้งค่าเครือข่าย)
- Windows services (บริการของ Windows)
- Server roles (บทบาทของเซิร์ฟเวอร์)
- Updates (อัปเดต)
- System properties (คุณสมบัติของระบบ)
--- notes
คุณสมบัติ Inventory ของ Systems Manager สามารถรวบรวมข้อมูลรายการของ EC2 instances และซอฟต์แวร์ที่ติดตั้งอยู่ เช่น:
- ข้อมูลแอปพลิเคชัน
- การตั้งค่าเครือข่าย
- บทบาทของเซิร์ฟเวอร์
- ไฟล์
- อัปเดต
- บริการของ Windows
- คุณสมบัติของระบบ
คุณสมบัติ Inventory ของ Systems Manager ช่วยให้เข้าใจการตั้งค่าระบบและแอปพลิเคชันที่ติดตั้งบน instances หลายเครื่องได้อย่างครอบคลุม โดยไม่ต้องล็อกอินเข้าแต่ละ instance ทีละเครื่อง
ข้อมูลที่รวบรวมได้ช่วยในการจัดการทรัพย์สินด้านแอปพลิเคชัน ติดตามใบอนุญาต เฝ้าติดตามความสมบูรณ์ของไฟล์ ค้นหาแอปพลิเคชันที่ไม่ได้ติดตั้งผ่านตัวติดตั้งแบบดั้งเดิม และอื่น ๆ

# AWS Systems Manager: Insights
**Insights dashboard** คือการแสดงข้อมูลการปฏิบัติการ (operational data) ของแต่ละทรัพยากร
ตัวอย่าง:
- API calls จาก **AWS CloudTrail**
- การเปลี่ยนแปลงการตั้งค่าทรัพยากรจาก **AWS Config**
- รายการซอฟต์แวร์ (Software inventory)
- สถานะความสอดคล้องของแพตช์ (patch compliance) แยกตาม resource group
แผนภาพ: Trusted Advisor notifications, CloudWatch Dashboards และ Personal Health Dashboard Alerts → ผสานรวมกับ Systems Manager Insights (Integrates with Systems Manager Insights)
--- notes
คุณสมบัติ Built-In Insights ของ AWS Systems Manager รวบรวมและแสดงข้อมูลการปฏิบัติการของแต่ละ resource group ผ่านแดชบอร์ด แดชบอร์ดนี้ทำให้ไม่ต้องสลับไปมาระหว่างคอนโซล AWS หลายหน้าเพื่อดูข้อมูลการปฏิบัติการ
ผู้ใช้สามารถดู:
- การเรียก application programming interface (API) จาก CloudTrail
- การเปลี่ยนแปลงการตั้งค่าทรัพยากรจาก AWS Config
- รายการซอฟต์แวร์
- สถานะ patch compliance แยกตาม resource group
ผู้ใช้ยังสามารถผสานรวม CloudWatch dashboards, การแจ้งเตือนของ Trusted Advisor และการแจ้งเตือนด้านประสิทธิภาพและความพร้อมใช้งานของ Personal Health Dashboard เข้ากับ Insights dashboard ได้

# AWS Tools for PowerShell
เขียนสคริปต์สั่งงานจากบรรทัดคำสั่ง PowerShell (หมวด AWS Tools and SDKs)
ตัวอย่าง:
- สร้างและตั้งค่า security groups
- launch instances
- สร้างและลบ Amazon S3 buckets
- ทำงานด้าน IAM
- เผยแพร่ (publish) Amazon CloudWatch metrics
--- notes
AWS Tools for PowerShell ช่วยให้คุณเขียนสคริปต์สั่งงานทรัพยากร AWS จากบรรทัดคำสั่ง PowerShell ทำการกระทำได้หลายอย่างเหมือนกับที่มีใน AWS SDK for .NET
คุณสามารถใช้ AWS Tools for PowerShell จากบรรทัดคำสั่งสำหรับงานด่วน เช่น:
- สร้างและตั้งค่า security groups
- launch instances
- สร้างและลบ S3 buckets
- ทำงานด้าน IAM เช่น กำหนด role ให้ผู้ใช้
- เผยแพร่ CloudWatch metrics
AWS Tools for Windows PowerShell มีชุด cmdlets ซึ่งเป็นคำสั่งที่ใช้ในสภาพแวดล้อม Windows PowerShell เพื่อทำการกระทำต่าง ๆ
AWS Tools for Windows PowerShell รองรับชุดบริการและ Regions เดียวกับที่ AWS SDKs รองรับ
ในห้าสไลด์ถัดไป คุณจะได้ทบทวนคำสั่ง PowerShell บางคำสั่ง ซึ่งใช้เพื่อ:
- launch instance
- ดูรายละเอียด EC2 instance โดยกรองด้วย reservation ID ก่อนหน้า
- สร้าง security group ใน Amazon Virtual Private Cloud (Amazon VPC)
- ดู security group ใหม่
- สร้าง S3 Bucket ใหม่
- สร้าง IAM group (-Path ไม่บังคับ)
- สร้าง IAM user ใหม่ (-Path ไม่บังคับ)
- เพิ่ม IAM user เข้า group

ตัวอย่างคำสั่ง PowerShell เพื่อสร้าง IAM group (-Path ไม่บังคับ):
```
PS C:\> New-IAMGroup -Path "/ps-created-groups/" -GroupName "powerUsers"
```

```
PS C:\> New-IAMUser -Path "/ps-created-users/" -UserName "myNewUser"
```

```
PS C:\> Add-IAMUserToGroup -UserName myNewUser -GroupName powerUsers
```

# SDKs
ภาษาที่รองรับ (ตามภาพ): JavaScript, Python, PHP, .NET, Ruby, Go, Node.js, C++, Java
--- notes
แนวคิด infrastructure as code (โครงสร้างพื้นฐานในรูปโค้ด) เป็นพื้นฐานของคลาวด์คอมพิวติ้ง และเป็นสิ่งที่ทำให้คลาวด์แตกต่างจากสภาพแวดล้อมไอทีแบบดั้งเดิม AWS software development kits (SDKs) และ application programming interfaces (APIs) มอบเครื่องมือที่จำเป็นให้แอปพลิเคชันที่สร้างบน AWS ถูกจัดการในรูปแบบ 'infrastructure as code'
AWS มี SDKs เฉพาะสำหรับแต่ละภาษา SDKs เหล่านี้มี APIs สำหรับภาษาที่แสดงบนสไลด์นี้ ทั้ง SDKs และ APIs ช่วยให้นักพัฒนานำการเชื่อมต่อและความสามารถของบริการ AWS ที่หลากหลายมาใช้ในโค้ดได้ โดยไม่ต้องเขียนฟังก์ชันขึ้นใหม่ตั้งแต่ต้น AWS SDKs มีเอกสารการใช้งานอย่างละเอียด รวมถึงคู่มือเริ่มต้นใช้งาน คู่มือนักพัฒนา เอกสารอ้างอิง API และฟอรัมชุมชนหรือบล็อกนักพัฒนา
ข้อมูลเพิ่มเติมเกี่ยวกับ AWS SDKs ดูได้ที่ https://aws.amazon.com/getting-started/tools-sdks

# AWS CloudFormation
- AWS CloudFormation ช่วยให้ผู้ใช้สร้าง อัปเดต และลบชุดทรัพยากรที่ครอบคลุมบริการ AWS หลายตัวเป็นหน่วยเดียว (stack)
- template ของ AWS CloudFormation เขียนด้วย JSON หรือ YAML
- คุณสมบัติหลัก ได้แก่:
  - ดูตัวอย่างล่วงหน้า (preview) ว่าการเปลี่ยนแปลงที่เสนอจะส่งผลต่อสภาพแวดล้อมอย่างไร
  - ตรวจจับการเบี่ยงเบน (Detect drift)
  - รองรับการขยายความสามารถ (Enable extensibility)

AWS CloudFormation เป็นอีกเครื่องมือที่มีประโยชน์ ซึ่งช่วยให้ผู้ใช้สร้าง อัปเดต หรือลบการ deploy โครงสร้างพื้นฐาน AWS ทั้งชุดได้อย่างคาดเดาได้และทำซ้ำได้
ด้วย AWS CloudFormation โครงสร้างพื้นฐานทั้งหมดสามารถจำลองไว้ในไฟล์ข้อความไฟล์เดียวที่เขียนด้วย JSON หรือ YAML template ที่เป็นไฟล์ข้อความนี้ใช้กำหนดทรัพยากร AWS ทั้งหมดที่ต้องการสำหรับ stack ได้ AWS CloudFormation stack คือกลุ่มของทรัพยากร AWS ที่จัดการเป็นหน่วยเดียวได้ กล่าวคือ คุณสามารถสร้าง อัปเดต หรือลบกลุ่มทรัพยากรได้ด้วยการสร้าง อัปเดต หรือลบ stacks ทรัพยากรใน stack อาจรวมถึง EC2 instances, Amazon Relational Database Service (Amazon RDS) instances, virtual private clouds (VPCs) และทรัพยากรอื่นอีกมากที่สร้างจากบริการ AWS
AWS CloudFormation ยังให้ผู้ใช้ดูล่วงหน้าได้ว่าการเปลี่ยนแปลงที่เสนอกับ stack อาจส่งผลต่อทรัพยากรที่กำลังทำงานอยู่อย่างไร เช่น การเปลี่ยนแปลงจะลบหรือแทนที่ทรัพยากรสำคัญใดหรือไม่ AWS CloudFormation จะทำการเปลี่ยนแปลงกับ stack ก็ต่อเมื่อผู้ใช้ตัดสินใจให้รันเท่านั้น
อีกคุณสมบัติหนึ่งของ AWS CloudFormation คือการตรวจจับการเบี่ยงเบน (drift detection) การรันการตรวจจับ drift กับ stack จะตัดสินว่า stack เบี่ยงเบนไปจากการตั้งค่าตาม template ที่คาดไว้หรือไม่ หากทรัพยากรใน stack รองรับการตรวจจับ drift การดำเนินการนี้จะส่งข้อมูลรายละเอียดเกี่ยวกับสถานะ drift ของทรัพยากรนั้นกลับมา

# AWS OpsWorks
AWS OpsWorks เป็น**บริการจัดการการตั้งค่า (configuration management service)**
- อิงกับ Chef และ Puppet
- ทำให้เกิด infrastructure as code ได้
- ทำให้สิ่งต่อไปนี้เป็นอัตโนมัติ:
  - โครงสร้างพื้นฐาน (Infrastructure)
  - การจัดการแอปพลิเคชัน (Application management)
  - การทดสอบการปฏิบัติตามข้อกำหนด (Compliance testing)
  - งานตั้งค่า (Configuration tasks)
มีให้เลือกสามแบบ (Three offerings available):
- AWS OpsWorks for Chef Automate (จัดการให้เต็มรูปแบบ – Fully managed)
- AWS OpsWorks for Puppet Enterprise (จัดการให้เต็มรูปแบบ – Fully managed)
- AWS OpsWorks Stacks
--- notes
AWS OpsWorks เป็นอีกเครื่องมือที่มีประโยชน์ เป็นบริการจัดการการตั้งค่าที่ให้ instances ของ Chef และ Puppet แบบมีผู้ดูแลให้ (managed) Chef และ Puppet เป็นแพลตฟอร์มอัตโนมัติที่ให้คุณใช้โค้ดทำให้การตั้งค่าเซิร์ฟเวอร์เป็นอัตโนมัติ OpsWorks ให้คุณใช้ Chef และ Puppet ทำให้การตั้งค่า การ deploy และการจัดการเซิร์ฟเวอร์บน EC2 instances หรือสภาพแวดล้อมการประมวลผล on-premises เป็นอัตโนมัติ
OpsWorks มีให้เลือกสามแบบ ได้แก่ AWS OpsWorks for Chef Automate, AWS OpsWorks for Puppet Enterprise และ AWS OpsWorks Stacks
ข้อมูลเพิ่มเติมเกี่ยวกับ AWS OpsWorks ดูได้ที่ https://aws.amazon.com/opsworks/
