=== S032
# การโฮสต์เว็บไซต์แบบสแตติกบน Amazon S3
แผนภาพ (ใน AWS Cloud):
- 1. สร้าง bucket ใน Amazon S3 (ในภาพคือ mompopcafe.com Amazon S3 bucket)
- 2. ตั้งค่า bucket ให้:
  - เปิดใช้การโฮสต์เว็บไซต์ (Enable website hosting)
  - ให้สิทธิ์อ่านแบบสาธารณะ (Grant public read permission)
- 3. อัปโหลดเนื้อหาเว็บไซต์ (ผ่าน AWS Management Console หรือ AWS Command Line Interface)
- 4. ไคลเอนต์ (Client) เข้าถึงเว็บไซต์ที่ endpoint ของ Amazon S3 ที่ได้รับ: http://mybucket-s3-website-us-west-2.amazonaws.com
--- notes
Amazon Simple Storage Service (Amazon S3) ให้บริการพื้นที่จัดเก็บแบบออบเจกต์ (object storage) และมีประโยชน์ใช้งานจริงมากมาย หนึ่งในนั้นคือการโฮสต์เว็บไซต์แบบสแตติก การใช้ Amazon S3 เพื่อจุดประสงค์นี้ช่วยให้ไม่ต้อง deploy โครงสร้างพื้นฐานขณะรัน (runtime infrastructure) ที่ซับซ้อนหรือมีค่าใช้จ่ายสูง เว็บไซต์แบบสแตติกประกอบด้วยหน้าเว็บแต่ละหน้าที่มีเนื้อหาแบบสแตติกและสคริปต์ฝั่งไคลเอนต์ (ถ้ามี) แต่หน้าเว็บเหล่านี้ไม่อาศัยการประมวลผลฝั่งเซิร์ฟเวอร์
การโฮสต์เว็บไซต์แบบสแตติกบน Amazon S3 มีขั้นตอนไม่กี่ขั้น:
- ขั้นแรก สร้าง bucket ใน Amazon S3 เพื่อเก็บเนื้อหาของเว็บไซต์
- จากนั้น ตั้งค่า S3 bucket ให้เปิดใช้การโฮสต์เว็บไซต์และให้สิทธิ์อ่านแบบสาธารณะกับเนื้อหา
- สุดท้าย อัปโหลดเนื้อหาเว็บไซต์ขึ้น bucket โดยใช้ Amazon Management Console หรือ AWS Command-line Interface (CLI)
- เข้าถึงเว็บไซต์ที่ URL ของ endpoint ที่ Amazon S3 กำหนดให้ URL ของ endpoint ประกอบด้วยชื่อ bucket และชื่อ Region ที่ bucket อยู่ ตามที่แสดงในแผนภาพ

=== S033
# การโฮสต์เว็บไซต์แบบสแตติกบน Amazon S3: ลักษณะเฉพาะ
สังเกตความแตกต่างของรูปแบบ URL ของ endpoint เว็บไซต์ อักขระคั่นก่อนชื่อ region จะเป็นจุดหรือขีด ขึ้นอยู่กับ Region ที่ S3 bucket อยู่
```
http://bucket-name.s3-website-region.amazonaws.com
http://bucket-name.s3-website.region.amazonaws.com
```
S3 bucket:
- ควรเก็บเว็บไซต์ในลำดับชั้นโฟลเดอร์ที่สะท้อนโครงสร้างเนื้อหา
- ต้องมี index document ที่กำหนดไว้ตอนตั้งค่า bucket
  - ชื่อค่าเริ่มต้นคือ index.html
--- notes
URL ของ endpoint ที่กำหนดให้เว็บไซต์แบบสแตติกที่โฮสต์ใน Amazon S3 จะเป็นไปตามหนึ่งในสองรูปแบบที่แสดงในสไลด์นี้ ดังที่กล่าวไปแล้ว URL ประกอบด้วยชื่อ bucket และชื่อ Region ที่สร้าง bucket ความแตกต่างระหว่างสองรูปแบบคือ อักขระคั่นก่อนชื่อ Region จะเป็นจุดหรือขีดขึ้นอยู่กับ Region ที่ bucket อยู่ ตัวอย่างเช่น หากสร้าง bucket ใน Region US West (Oregon) อักขระคั่นจะเป็นขีด แต่หากสร้าง bucket ใน Region EU (Frankfurt) อักขระคั่นจะเป็นจุด
**หมายเหตุ (NOTE):** เนื้อหาเว็บที่อัปโหลดควรเก็บในลำดับชั้นโฟลเดอร์ของ Amazon S3 ที่สะท้อนโครงสร้างเนื้อหาของเว็บไซต์ นอกจากนี้ เมื่อเปิดใช้ bucket สำหรับโฮสต์เว็บไซต์ ต้องระบุชื่อของ index document ซึ่งเป็นหน้าเว็บเริ่มต้นที่ Amazon S3 ส่งกลับเมื่อมีคำขอมายังรากของเว็บไซต์หรือโฟลเดอร์ย่อยใดโฟลเดอร์หนึ่ง ตรวจสอบให้แน่ใจว่าเนื้อหาเว็บที่โหลดขึ้นไปมี index document นี้อยู่ในระดับโฟลเดอร์ที่ถูกต้อง

=== S034
# การใช้โดเมนของตนเอง (custom domain)
ไคลเอนต์เข้าถึง http://www.mompopcafe.com และ http://mompopcafe.com
ตาราง alias ใน Amazon Route 53:
| Name | Alias Target |
| mompopcafe.com | http://mompopcafe.com-s3-website-us-west-2.amazonaws.com |
| www.mompopcafe.com | http://www.mompopcafe.com-s3-website-us-west-2.amazonaws.com |
ใน AWS Cloud: www.mompopcafe.com Amazon S3 bucket → เปลี่ยนเส้นทาง (Redirect) → mompopcafe.com Amazon S3 bucket
--- notes
แทนที่จะเข้าถึงเว็บไซต์แบบสแตติกผ่าน URL ของ endpoint ของ Amazon S3 ผู้ใช้สามารถเลือกใช้บริการ Amazon Route 53 เพื่อจับคู่ชื่อโดเมนของตนเองกับ endpoint ของ Amazon S3 ได้ ตัวอย่างเช่น ผู้ใช้อาจกำหนดชื่อโดเมน mompopcafe.com หรือกำหนดชื่อโดเมนย่อย เช่น www.mompopcafe.com
ในตัวอย่างบนสไลด์นี้ ใช้ทั้งโดเมนหลัก mompopcafe.com และโดเมนย่อย www.mompopcafe.com ในการเข้าถึงเว็บไซต์ เพื่อรองรับสิ่งนี้ จึงสร้างและตั้งค่า bucket สองตัวใน Amazon S3 ชื่อละหนึ่ง bucket โดย bucket หนึ่งเก็บเนื้อหาเว็บไซต์ และอีก bucket หนึ่งเปลี่ยนเส้นทางคำขอไปยัง bucket ที่เก็บเนื้อหา สังเกตว่าชื่อ bucket ต้องตรงกับชื่อโดเมนที่ใช้ นอกจากนี้ยังสร้าง alias records ใน Amazon Route 53 เพื่อจับคู่ชื่อโดเมนและโดเมนย่อยกับ endpoint ของ S3 bucket ที่สอดคล้องกัน

=== S046
# AWS กับโลกจริง
Amazon Web Services (AWS) มีบริการหลากหลายหมวดหมู่ เช่น:
- Compute (การประมวลผล)
- Storage (การจัดเก็บข้อมูล)
- Database (ฐานข้อมูล)
- Analytics (การวิเคราะห์ข้อมูล)
AWS มอบโซลูชันบนคลาวด์ให้ทั้งองค์กรขนาดใหญ่และธุรกิจขนาดเล็ก เพื่อขับเคลื่อนการดำเนินงานไปข้างหน้า:
- ได้เร็วขึ้น
- ด้วยต้นทุนที่ลดลง
- พร้อมความสามารถในการขยายขนาดตามความต้องการ
--- notes
Amazon Web Services (AWS) มีบริการหลากหลายหมวดหมู่ เช่น การประมวลผล การจัดเก็บข้อมูล ฐานข้อมูล และการวิเคราะห์ข้อมูล ซึ่งเปิดโอกาสให้ทั้งองค์กรขนาดใหญ่และธุรกิจขนาดเล็กใช้เทคโนโลยีขับเคลื่อนการดำเนินงานไปข้างหน้าได้เร็วขึ้น ด้วยต้นทุนที่ลดลง และสามารถขยายขนาดตามความต้องการได้
