# โมดูล 9: Lab 6 – การเฝ้าติดตามโครงสร้างพื้นฐาน (Monitoring Infrastructure)
ความสามารถในการเฝ้าติดตามแอปพลิเคชันและโครงสร้างพื้นฐานมีความสำคัญอย่างยิ่งต่อการให้บริการไอทีที่เชื่อถือได้และสม่ำเสมอ
ความต้องการด้านการเฝ้าติดตามมีตั้งแต่การเก็บสถิติเพื่อวิเคราะห์ระยะยาว ไปจนถึงการตอบสนองต่อการเปลี่ยนแปลงและเหตุขัดข้องอย่างรวดเร็ว การเฝ้าติดตามยังสนับสนุนการรายงานการปฏิบัติตามข้อกำหนด (compliance) ด้วยการตรวจสอบอย่างต่อเนื่องว่าโครงสร้างพื้นฐานเป็นไปตามมาตรฐานขององค์กร
แล็บนี้แสดงวิธีใช้ Amazon CloudWatch Metrics, Amazon CloudWatch Logs, Amazon CloudWatch Events และ AWS Config เพื่อเฝ้าติดตามแอปพลิเคชันและโครงสร้างพื้นฐาน
แล็บจะสาธิตวิธี:
- ใช้ AWS Systems Manager Run Command ติดตั้ง CloudWatch Agent บน Amazon EC2 instances
- เฝ้าติดตาม Application Logs ด้วย CloudWatch Agent และ CloudWatch Logs
- เฝ้าติดตาม system metrics ด้วย CloudWatch Agent และ CloudWatch Metrics
- สร้างการแจ้งเตือนแบบเรียลไทม์ด้วย CloudWatch Events
- ติดตามการปฏิบัติตามข้อกำหนดของโครงสร้างพื้นฐานด้วย AWS Config

## งานที่ 1: ติดตั้ง CloudWatch Agent
CloudWatch Agent ใช้เก็บ metrics จาก Amazon EC2 instances และเซิร์ฟเวอร์ on-premises ได้ ได้แก่:
- **System-level metrics จาก Amazon EC2 instances** เช่น การจัดสรร CPU พื้นที่ดิสก์ว่าง และการใช้หน่วยความจำ metrics เหล่านี้เก็บจากตัวเครื่องเอง และเสริม metrics มาตรฐานที่ CloudWatch เก็บอยู่แล้ว
- **System-level metrics จากเซิร์ฟเวอร์ on-premises** ทำให้เฝ้าติดตามสภาพแวดล้อมแบบไฮบริดและเซิร์ฟเวอร์ที่ AWS ไม่ได้จัดการได้
- **System and Application Logs** จากเซิร์ฟเวอร์ทั้ง Linux และ Windows
- **Custom metrics** จากแอปพลิเคชันและบริการ โดยใช้โปรโตคอล StatsD (https://github.com/etsy/statsd) และ collectd (https://collectd.org/)
ในงานนี้ คุณจะใช้ AWS Systems Manager ติดตั้ง CloudWatch Agent บน Amazon EC2 instance และตั้งค่าให้เก็บทั้ง metrics ของแอปพลิเคชันและของระบบ

## งานที่ 2: เฝ้าติดตาม Application Logs ด้วย CloudWatch Logs
คุณใช้ Amazon CloudWatch Logs เฝ้าติดตามแอปพลิเคชันและระบบโดยใช้ข้อมูล log ได้ ตัวอย่างเช่น CloudWatch Logs ติดตามจำนวนข้อผิดพลาดที่เกิดใน log ของแอปพลิเคชัน และส่งการแจ้งเตือนเมื่ออัตราข้อผิดพลาดเกินเกณฑ์ที่คุณกำหนด
CloudWatch Logs ใช้ข้อมูล log ที่มีอยู่ในการเฝ้าติดตาม จึงไม่ต้องแก้โค้ด ตัวอย่างเช่น คุณเฝ้าติดตาม logs ของแอปพลิเคชันหาคำเฉพาะ (เช่น "NullReferenceException") หรือนับจำนวนครั้งที่คำเฉพาะปรากฏในตำแหน่งหนึ่งของข้อมูล log (เช่น รหัสสถานะ "404" ใน access log ของเว็บเซิร์ฟเวอร์) ได้ เมื่อพบคำที่ค้นหา CloudWatch Logs จะรายงานข้อมูลไปยัง CloudWatch metric ที่คุณระบุ ข้อมูล log ถูกเข้ารหัสทั้งระหว่างส่งและขณะจัดเก็บ
ในงานนี้ คุณจะสร้างข้อมูล log บน Web Server แล้วเฝ้าติดตาม logs ด้วย CloudWatch Logs
> [แผนภาพ CloudWatch Logs]
Web Server สร้างข้อมูล log สองประเภท:
- Access Logs
- Error Logs
