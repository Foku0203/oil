## งานที่ 1: launch Amazon EC2 Instance โดยใช้ Management Console
### ขั้นที่ 1: เริ่มสร้าง instance และตั้งชื่อ
ในงานนี้ คุณจะ launch Amazon EC2 instance โดยใช้ management console instance นี้จะเป็น Bastion Server ซึ่งคุณจะใช้ AWS Command-Line Interface (AWS CLI) จากเครื่องนี้
- 5. เลือกเมนู **Services** หาบริการกลุ่ม **Compute** แล้วเลือก **EC2**
- 6. เลือกปุ่ม **Launch instance** ตรงกลางหน้า แล้วเลือก **Launch instance** จากเมนูดรอปดาวน์
- 7. ตั้งชื่อ instance:
  - ตั้งชื่อว่า `Bastion Server`
  - *Tags* ช่วยให้จัดหมวดหมู่ทรัพยากร AWS ได้หลายแบบ เช่น ตามวัตถุประสงค์ เจ้าของ หรือสภาพแวดล้อม มีประโยชน์เมื่อคุณมีทรัพยากรประเภทเดียวกันจำนวนมาก – คุณระบุทรัพยากรเฉพาะได้อย่างรวดเร็วด้วย tags แต่ละ tag ประกอบด้วย _Key_ และ _Value_ ซึ่งคุณกำหนดเองทั้งคู่
  - **หมายเหตุ:** *Name* เป็นเพียง tag อีกตัวหนึ่ง *key* ของ tag นี้คือ `Name` และ *value* คือ `Web Server 1` (ตามต้นฉบับ) ชื่อนี้จะแสดงบน instance ใน EC2 management console
### ขั้นที่ 2: Application and OS Images
ขั้นนี้ให้คุณเลือก AMI ซึ่งมีสำเนาของ disk volume ที่จะใช้ launch instance
หมายเหตุ: ดูรายการ AMIs ที่แสดง ซึ่งมี Microsoft Windows และ Linux หลายเวอร์ชัน disk images เหล่านี้ถูกอัปเดตเป็นประจำเพื่อรวมแพตช์ความปลอดภัยและซอฟต์แวร์ที่ช่วยให้คุณใช้บริการ AWS คุณยังสร้าง AMI ของตัวเองที่มีข้อมูลและแอปพลิเคชันของคุณ หรือเลือกแอปพลิเคชันเชิงพาณิชย์ที่สร้างไว้แล้วจาก **AWS Marketplace** ได้
- 8. เลือก AMI ที่จะใช้สร้าง instance:
  - ในรายการ AMIs แบบ *Quick Start* ให้คง AMI ค่าเริ่มต้น **Amazon Linux** ไว้
  - และคง **Amazon Linux 2023 AMI** ค่าเริ่มต้นไว้เช่นกัน
### ขั้นที่ 3: เลือก Instance Type
ขั้นนี้ให้คุณเลือก **Instance Type** ซึ่งกำหนดทรัพยากรที่จะจัดสรรให้ EC2 instance แต่ละ Instance Type จัดสรร CPU เสมือน หน่วยความจำ พื้นที่ดิสก์ และสมรรถนะเครือข่ายในสัดส่วนต่างกัน
Instance Types แบ่งเป็น **ตระกูล (families)** เช่น Compute-optimized, Memory-optimized และ Storage-Optimized ชื่อ Instance Type ประกอบด้วยตัวระบุตระกูล เช่น **t3** และ **m4** ตัวเลขบอก _รุ่น (generation)_ ของ instance ดังนั้น **m5** ใหม่กว่า **m4**
- 9. ระบุ Instance type:
  - ในแผง *Instance type* คง **t3.micro** ค่าเริ่มต้นไว้
  - instance type นี้มี CPU เสมือน 1 ตัว และหน่วยความจำ 1 GiB เป็น instance ที่สามารถเร่งสมรรถนะเกินระดับพื้นฐาน (burst) ได้เมื่อมีงานมาก เหมาะสำหรับการพัฒนา การทดสอบ และแอปพลิเคชันที่มีภาระงานเป็นช่วง ๆ
### ขั้นที่ 4: เลือก key pair
- 10. เลือก key pair ที่จะผูกกับ instance:
  - จากเมนู **Key pair name** เลือก **vockey**
  - key pair *vockey* ที่เลือกจะทำให้คุณเชื่อมต่อกับ instance นี้ผ่าน SSH ได้หลัง launch แล้ว
### ขั้นที่ 5: การตั้งค่าเครือข่าย (Network settings)
คุณจะ launch instance ใน public subnet ภายในเครือข่าย _Lab VPC_
- 11. ข้าง Network settings เลือก **Edit**
- 12. ที่ **VPC** เลือก **Lab VPC**
- 13. ที่ **Subnet** ยอมรับค่า Public Subnet
- 14. คงการตั้งค่า **Auto-assign public IP** เป็น **Enable**
- 15. ใต้ *Firewall (security groups)* คงตัวเลือกค่าเริ่มต้น **Create security group** ไว้
  - คุณจะสร้าง Security Group ใหม่ที่อนุญาตการเชื่อมต่อ SSH เพื่อให้ล็อกอินเข้า Bastion Server ผ่าน SSH ได้
- 16. ตั้งค่า security group:
  - **Security group name:** `Bastion security group`
  - **Description:** `Permit SSH connections`
  - สิทธิ์ขาเข้าผ่าน SSH (พอร์ต 22) ถูกตั้งค่าไว้แล้วโดยค่าเริ่มต้น ให้คงการตั้งค่าเหล่านี้ไว้
### ขั้นที่ 6: ตั้งค่าพื้นที่จัดเก็บ (Configure storage)
ขั้นนี้ใช้เพิ่ม Amazon Elastic Block Store (EBS) disk volumes และตั้งค่าขนาดและสมรรถนะได้ คุณสามารถวางเมาส์บนไอคอน (i) เพื่อดูคำอธิบายของแต่ละช่อง
- 17. ในส่วน *Configure storage* คงการตั้งค่าเริ่มต้นไว้
### ขั้นที่ 7: รายละเอียดขั้นสูง (Advanced details)
- 18. ขยายแผง **Advanced details** และที่ **IAM instance profile** เลือก **Bastion-Role**
  - _Bastion-Role_ ให้สิทธิ์แอปพลิเคชันที่รันบน instance ส่งคำขอไปยังบริการ Amazon EC2 ได้ ซึ่งจำเป็นสำหรับครึ่งหลังของแล็บ ที่คุณจะใช้ AWS CLI สื่อสารกับบริการ EC2
### ขั้นที่ 8: launch instance
- 19. ที่ด้านล่างของแผง **Summary** ทางขวาของหน้าจอ เลือก **Launch instance**
  - คุณจะเห็นข้อความแจ้งสำเร็จ (Success)
- 20. เลือก **View all instances**
  - instance **Bastion Server** จะปรากฏในสถานะ *Pending* ก่อน หมายถึงกำลัง launch จากนั้นสถานะจะเปลี่ยนเป็น *Running* หมายถึง instance เริ่มบูตแล้ว instance ใช้เวลาบูตไม่กี่นาที
- 21. เลือก instance **Bastion Server** แล้วทบทวนข้อมูลในแท็บ **Details** ที่แสดงในแผงด้านล่าง
  - สังเกตว่า instance มี **Public IPv4 address** คุณใช้ IP address นี้สื่อสารกับ instance จากอินเทอร์เน็ตได้
- 22. ก่อนทำต่อ ให้รอจน instance แสดงสิ่งต่อไปนี้:
  - **Instance state:** *Running*
  - **Status check:** *2/2 checks passed*
  - หมายเหตุ: อาจใช้เวลาไม่กี่นาที เลือกไอคอนรีเฟรชที่ด้านบนของหน้าทุก ๆ ประมาณ 30 วินาที เพื่อให้รู้สถานะล่าสุดของ instance ได้เร็วขึ้น

## งานที่ 3: launch Instance โดยใช้ AWS CLI
ในงานนี้ คุณจะ launch Amazon EC2 instance โดยใช้ AWS Command-Line Interface (CLI) AWS CLI ทำให้การจัดเตรียมและตั้งค่าทรัพยากร AWS เป็นอัตโนมัติได้ง่าย
instance ใหม่จะถูกตั้งค่าเป็น Web Server
### หา AMI ที่จะใช้
พารามิเตอร์หนึ่งที่จำเป็นเมื่อ launch instance คือ Amazon Machine Image (AMI) ซึ่งจะเป็นข้อมูลในดิสก์บูตของ instance AWS ติดตั้งแพตช์และอัปเดต AMIs อย่างต่อเนื่อง จึงแนะนำให้ใช้ AMI ล่าสุดเสมอเมื่อ launch instances
คุณจะใช้ **AWS Systems Manager Parameter Store** เพื่อหา ID ของ AMI _Amazon Linux 2023_ ล่าสุด AWS ดูแลรายการ AMIs มาตรฐานไว้ใน Parameter Store ทำให้งานนี้ทำเป็นอัตโนมัติได้ง่าย
- 37. วางสคริปต์นี้ใน session ของ PuTTY/ssh:
```
# Get token
TOKEN=$(curl --request PUT "http://169.254.169.254/latest/api/token" --header "X-aws-ec2-metadata-token-ttl-seconds: 21600")
# Set the Region
AZ=$(curl --write-out "\n" --request GET "http://169.254.169.254/latest/meta-data/placement/availability-zone" --header "X-aws-ec2-metadata-token: $TOKEN")
export AWS_DEFAULT_REGION=${AZ::-1}
# Obtain latest Linux AMI
AMI=$(aws ssm get-parameters --names /aws/service/ami-amazon-linux-latest/amzn2-ami-hvm-x86_64-gp2 --query 'Parameters[0].[Value]' --output text)
echo $AMI
```
คำสั่งนี้ทำสิ่งต่อไปนี้:
- สร้าง token ที่ใช้กับ Instance Metadata Service v2 (IMDSv2)
- หา Region ที่ instance กำลังรันอยู่
- เรียก AWS Systems Manager (_ssm_) และใช้คำสั่ง **get-parameters** ดึงค่าจาก Parameter Store
- AMI ที่ขอคือ Amazon Linux 2023 (_al2023-ami_) (หมายเหตุผู้แปล: ในสคริปต์ต้นฉบับใช้พาธ amzn2-ami-hvm-x86_64-gp2 ซึ่งเป็น Amazon Linux 2)
- AMI ID ถูกเก็บไว้ใน Environment Variable ชื่อ _AMI_
> คำเตือน: หาก SSH session หลุด ข้อมูลที่เก็บใน environment variables จะหายไป เมื่อเชื่อมต่อใหม่ คุณต้องรันทุกขั้นตอนในงานนี้ใหม่ทั้งหมด เริ่มจากคำสั่งข้างต้นเพื่อหา AMI ID
### หา Subnet ที่จะใช้
คุณจะ launch instance ใหม่ใน Public Subnet เมื่อ launch instance สามารถระบุ **SubnetId** ได้
คำสั่งต่อไปนี้จะดึง _SubnetId_ ของ Public Subnet:
- 38. วางคำสั่งนี้:
```
SUBNET=$(aws ec2 describe-subnets --filters 'Name=tag:Name,Values=Public Subnet' --query Subnets[].SubnetId --output text)
echo $SUBNET
```
- คำสั่งนี้ใช้ AWS CLI ดึง Subnet ID ของ subnet ชื่อ _Public Subnet_
### หา Security Group ที่จะใช้
แล็บนี้เตรียม _Web Security Group_ ไว้ให้แล้ว ซึ่งอนุญาตคำขอ HTTP ขาเข้า
- 39. วางคำสั่งนี้:
```
SG=$(aws ec2 describe-security-groups --filters Name=group-name,Values=WebSecurityGroup --query SecurityGroups[].GroupId --output text)
echo $SG
```
- คำสั่งนี้ดึง _Security Group ID_ ของ Web Security Group
### ดาวน์โหลดสคริปต์ User Data
คุณจะ launch instance ที่ทำหน้าที่เป็น Web Server เพื่อติดตั้งและตั้งค่าเว็บเซิร์ฟเวอร์ คุณจะให้ **User Data script** ซึ่งจะรันอัตโนมัติเมื่อ instance launch
- 40. วางคำสั่งนี้เพื่อดาวน์โหลดสคริปต์ User Data:
```
wget https://aws-tc-largeobjects.s3.amazonaws.com/ILT-TF-200-ACSOPS-1/lab-2-ec2-linux/UserData.txt
```
- 41. วางคำสั่งนี้เพื่อดูเนื้อหาของสคริปต์:
```
cat UserData.txt
```
สคริปต์ทำสิ่งต่อไปนี้:
- ติดตั้งเว็บเซิร์ฟเวอร์
- ดาวน์โหลดไฟล์ zip ที่มีเว็บแอปพลิเคชัน
- ติดตั้งเว็บแอปพลิเคชัน
### launch Instance
ตอนนี้คุณมีข้อมูลที่จำเป็นทั้งหมดในการ launch Web Server instance แล้ว!
- 42. วางคำสั่งนี้:
```
INSTANCE=$(\
aws ec2 run-instances \
--image-id $AMI \
--subnet-id $SUBNET \
--security-group-ids $SG \
--user-data file:///home/ec2-user/UserData.txt \
--instance-type t3.micro \
--tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=Web Server}]' \
--query 'Instances[*].InstanceId' \
--output text \
)
echo $INSTANCE
```
คำสั่งนี้ launch instance ใหม่ (_run_instances_) ด้วยพารามิเตอร์ต่อไปนี้:
- **Image:** ใช้ค่า AMI ที่ได้จาก Parameter Store ก่อนหน้า
- **Subnet:** ระบุ _Public Subnet_ ที่ได้ก่อนหน้า ซึ่งโดยนัยก็คือ VPC ที่จะ launch instance
- **Security Group:** ใช้ _Web Security Group_ ที่ได้ก่อนหน้า ซึ่งอนุญาตการเข้าถึง HTTP
- **User Data:** อ้างอิงสคริปต์ User Data ที่ดาวน์โหลดไว้ ซึ่งติดตั้งเว็บแอปพลิเคชัน
- **Instance Type:** ระบุประเภทของ instance ที่จะ launch
- **Tags:** กำหนด tag _Name_ ด้วยค่า _Web Server_
พารามิเตอร์ **query** ระบุให้คำสั่งส่ง _Instance ID_ กลับมาเมื่อ launch instance แล้ว
พารามิเตอร์ **output** ระบุให้ผลลัพธ์ของคำสั่งเป็น _text_ ตัวเลือกผลลัพธ์อื่นคือ _json_ และ _table_
ID ของ instance ใหม่ถูกเก็บไว้ใน environment variable ชื่อ _INSTANCE_
### รอให้ Instance พร้อมใช้งาน
คุณเฝ้าดูสถานะของ instance ผ่าน Management Console ได้ แต่ก็ query สถานะผ่าน AWS CLI ได้เช่นกัน
- 43. วางคำสั่งนี้:
```
aws ec2 describe-instances --instance-ids $INSTANCE
```
- ข้อมูลทั้งหมดที่เกี่ยวกับ instance จะแสดงในรูปแบบ JSON ซึ่งรวมถึงสถานะของ instance
- สามารถดึงข้อมูลเฉพาะได้ด้วยพารามิเตอร์ **query**
- 44. วางคำสั่งนี้:
```
aws ec2 describe-instances --instance-ids $INSTANCE --query 'Reservations[].Instances[].State.Name' --output text
```
- เป็นคำสั่งเดิม แต่แทนที่จะแสดงข้อมูลทั้งหมดของ instance จะแสดงเฉพาะชื่อ _State_ ของ instance
- จะแสดงสถานะ **pending** หรือ **running**
- รันคำสั่งข้างต้นซ้ำจนได้สถานะ **running**
### ทดสอบ Web Server
ตอนนี้คุณทดสอบได้ว่าเว็บเซิร์ฟเวอร์ทำงาน คุณดึง URL ของ instance ผ่าน AWS CLI ได้
- 45. วางคำสั่งนี้:
```
aws ec2 describe-instances --instance-ids $INSTANCE --query Reservations[].Instances[].PublicDnsName --output text
```
- คำสั่งนี้ส่ง **DNS Name** ของ instance กลับมา
- 46. คัดลอก DNS name ที่แสดง
  - ควรมีลักษณะคล้าย: _ec2-35-11-22-33.compute-1.amazonaws.com_
- 47. วาง DNS name ในแท็บเบราว์เซอร์ใหม่ แล้วกด Enter
  - หน้าเว็บควรแสดงขึ้น แสดงว่าเว็บเซิร์ฟเวอร์ถูก launch และตั้งค่าสำเร็จ
  - คุณยังเห็น instance ใน EC2 management console ได้ด้วย
- 48. กลับไปที่แท็บเบราว์เซอร์ที่มี EC2 management console
- 49. ในหน้า **Instances** เลือก Refresh
  - รายการควรมี instance _Web Server_ ที่ launch ผ่านคำสั่ง AWS CLI แล้ว
  - ดังที่เห็นในงานนี้ AWS CLI ทำให้เข้าถึงและควบคุมบริการ AWS ผ่านโปรแกรมได้ คำสั่งเหล่านี้ใส่ในสคริปต์และรันเป็นกระบวนการมาตรฐาน เพื่อ deploy โครงสร้างพื้นฐานที่สม่ำเสมอและเชื่อถือได้ โดยลดโอกาสผิดพลาดจากคน
**ควรใช้วิธีใด?**
- **launch จาก management console** เมื่อต้องการ launch instance ที่ใช้ครั้งเดียวหรือชั่วคราวอย่างรวดเร็ว
- **launch ผ่านสคริปต์** เมื่อต้องการทำให้การสร้าง instance เป็นอัตโนมัติ ทำซ้ำได้และเชื่อถือได้
- **launch ผ่าน CloudFormation** เมื่อต้องการ launch ทรัพยากรที่เกี่ยวข้องกันพร้อมกัน
