=== P006
# การทำเวอร์ชวลไลเซชันของ Amazon EC2 (Amazon EC2 virtualization)
แผนภาพ: Amazon EC2 instances ทำงานบน Hypervisor ซึ่งอยู่บนฮาร์ดแวร์ที่มี CPUs, RAM, Network และ Instance store (ชั่วคราว – ephemeral) เชื่อมต่อกับ Internet
- เชื่อมต่อกับ Amazon Simple Storage Service (Amazon S3)
- เชื่อมต่อกับ Amazon Elastic Block Store (Amazon EBS) ผ่านการเชื่อมต่อแบบ EBS-optimized

=== P007
# ประเภทของ instance (Instance types)
- **หมวดหมู่ (Categories):** General purpose (ใช้งานทั่วไป), Compute optimized (เน้นการประมวลผล), Memory optimized (เน้นหน่วยความจำ), Accelerated computing (ใช้ตัวเร่งการประมวลผล), Storage optimized (เน้นพื้นที่จัดเก็บ)
- **ตระกูล (Families):** กลุ่มของประเภท (types) ภายในหมวดหมู่หนึ่ง
- **ประเภท (Types):** ชุดความสามารถของฮาร์ดแวร์เสมือนที่ไม่ซ้ำกัน เช่น t3.nano ถึง x1e.32xlarge
- **ความแปรผัน (Variations):**
  - ชนิดของ CPU (CPU type)
  - จำนวน CPU หรือคอร์ (CPU or core count)
  - ขนาดหน่วยความจำ (Memory amount)
  - ชนิดพื้นที่จัดเก็บ (Storage type)
  - ขนาดพื้นที่จัดเก็บ (Storage amount)
  - ประสิทธิภาพเครือข่าย (Network performance)

=== P009
# Amazon Machine Image (AMI)
**AMI ประกอบด้วย:**
- แม่แบบ (template) สำหรับ volumes ของ instance
- สิทธิ์ในการ launch (Launch permissions)
- การจับคู่อุปกรณ์บล็อก (Block device mappings)
**ตัวเลือก AMI:**
- AWS Provided (AWS จัดเตรียมให้)
- User Built (ผู้ใช้สร้างเอง)
- Community (จากชุมชน)
- Marketplace (จาก AWS Marketplace)

=== P011
# เครือข่ายของ Amazon EC2 (Amazon EC2 networking)
แผนภาพ (AWS Cloud → VPC → Availability Zone 2):
- Public Subnet: EC2 instances อยู่ใน security group เชื่อมต่อกับ Internet ผ่าน Internet gateway ให้ไคลเอนต์ (Client) เข้าถึงได้
- Private subnet: EC2 instances อยู่ใน security groups ของตน
- ศูนย์ข้อมูลขององค์กร (Corporate data center): ไคลเอนต์ขององค์กร (Corporate client) → Customer gateway → VPN → VPN gateway → VPC

=== P012
# IP address แบบ private, public และ elastic
- Public IP address จะเปลี่ยนเมื่อหยุด (stop) แล้วเริ่ม instance ใหม่

=== P013
# Security groups
- จำกัดการเข้าถึง instances ด้วย:
  - ช่วงพอร์ต (Port range)
  - ช่วง IP address (IP address range)
  - Resource ID
- instances สามารถผูกกับหลาย security groups ได้
- ควบคุมข้อมูลขาเข้า (ingress) และขาออก (egress)
- เพิ่มหรือแก้ไขได้หลังจาก launch
ตัวอย่างการตั้งค่า security group:
- NAT: Remote Access ที่พอร์ต 22
- Web servers: Remote Access ที่พอร์ต 22 และ Web traffic ที่พอร์ต 80
- DB: พอร์ต 3306

=== P015
# Instance profile
- หลีกเลี่ยงการเก็บ access key และ secret key ไว้ในเครื่อง EC2
- ช่วยให้แนบ IAM role เข้ากับ EC2 instance ได้
- กระจาย access keys ไปยัง instances โดยอัตโนมัติ
- หมุนเวียน (rotate) access keys อัตโนมัติหลายครั้งต่อวัน
- ใช้กับหลาย instances ได้ (เช่น Auto Scaling group)
ตัวอย่าง: ให้สิทธิ์ EC2 instances เข้าถึง Amazon S3 buckets ที่เก็บข้อมูลของแอปพลิเคชัน
> **แนวปฏิบัติที่ดีที่สุด (Best Practice):** อย่าเก็บ access keys แบบถาวรไว้บน EC2 instances เพราะ credentials อาจรั่วไหลได้

=== P020
# Amazon EC2 instance metadata
- ข้อมูลเกี่ยวกับ instance ของคุณ ที่ใช้ตั้งค่าหรือจัดการ instance ที่กำลังทำงานได้
- บริการ metadata มีให้ทุก instance ที่ IP address 169.254.169.254
- การ query instance metadata:
Linux:
```
export INSTANCE_ID=$(curl http://169.254.169.254/latest/meta-data/instance-id)
aws ec2 describe-instances --instance-id $INSTANCE_ID
```
Windows:
```
$INSTANCE_ID=(new-object net.webclient).DownloadString(
'http://169.254.169.254/latest/meta-data/instance-id')
aws ec2 describe-instances --instance-id $INSTANCE_ID
```

=== P021
# User data และ Amazon EC2 instance metadata
- การอ้างอิงคุณสมบัติของ instance ใน user data อาจมีประโยชน์
- query instance metadata แล้วนำไปใช้ในสคริปต์ user data ตอน launch
ตัวอย่าง: เปลี่ยน hostname ของ Amazon Linux AMI ให้เป็น instance-id ตอน launch (User Data Script, Linux):
```
#!/bin/bash
#Get hostname from instance-id metadata = $newhost
newhost=$(curl http://169.254.169.254/latest/meta-data/instance-id/)
#change hostname in /etc/hosts & /etc/sysconfig/network
sudo sed -i "s/\<localhost\>/$newhost/g" /etc/hosts
sudo sed -i "s/\<localhost\>/$newhost/g" /etc/sysconfig/network
#Reboot instance
sudo reboot
```
(คอมเมนต์ในสคริปต์: ดึง hostname จาก metadata instance-id เก็บใน $newhost → เปลี่ยน hostname ใน /etc/hosts และ /etc/sysconfig/network → รีบูต instance)
