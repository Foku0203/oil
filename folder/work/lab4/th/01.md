## ภาพรวมและวัตถุประสงค์ของแล็บ
เครือข่ายแบบดั้งเดิมนั้นยาก ต้องใช้อุปกรณ์ การเดินสาย การตั้งค่าที่ซับซ้อน และทักษะเฉพาะทาง โชคดีที่ Amazon VPC ซ่อนความซับซ้อนเหล่านี้ไว้ และทำให้ deploy เครือข่ายส่วนตัวที่ปลอดภัยได้ง่าย

## งานที่ 1: สร้าง VPC
คุณจะเริ่มด้วยการสร้าง Virtual Private Cloud (VPC) ใหม่
VPC คือเครือข่ายเสมือนที่อุทิศให้บัญชี AWS ของคุณ แยกออกจากเครือข่ายเสมือนอื่นใน AWS cloud ในเชิงตรรกะ คุณ launch ทรัพยากร AWS เช่น Amazon EC2 instances เข้าไปใน VPC ได้ คุณตั้งค่า VPC ได้โดยแก้ไขช่วง IP address สร้าง subnets และตั้งค่า route tables, network gateways และการตั้งค่าความปลอดภัย

### สร้าง Private Subnet

ตอนนี้ VPC ของคุณมีสอง subnets แต่ VPC ยังแยกขาดโดยสิ้นเชิงและสื่อสารกับทรัพยากรภายนอก VPC ไม่ได้ ต่อไปคุณจะตั้งค่า Public Subnet ให้เชื่อมต่ออินเทอร์เน็ตผ่าน Internet Gateway
## งานที่ 3: สร้าง Internet Gateway
internet gateway คือส่วนประกอบของ VPC ที่ขยายขนาดแนวนอน มีความซ้ำซ้อน และพร้อมใช้งานสูง ซึ่งให้ instances ใน VPC สื่อสารกับอินเทอร์เน็ตได้ ไม่ก่อความเสี่ยงด้านความพร้อมใช้งานหรือข้อจำกัดแบนด์วิดท์ต่อทราฟฟิกเครือข่าย
internet gateway มีวัตถุประสงค์สองประการ:
- เป็นเป้าหมาย (target) ใน route tables เพื่อเชื่อมต่ออินเทอร์เน็ต
- ทำ network address translation (NAT) ให้ instances ที่ได้รับ IPv4 Public IP addresses
ในงานนี้ คุณจะสร้าง internet gateway เพื่อให้ทราฟฟิกอินเทอร์เน็ตเข้าถึง public subnet ได้
- 15. ในแถบนำทางด้านซ้าย เลือก **Internet gateways**

## งานที่ 4: ตั้งค่า Route Tables
route table ประกอบด้วยชุดของกฎที่เรียกว่า routes ซึ่งใช้กำหนดว่าทราฟฟิกเครือข่ายจะถูกส่งไปที่ใด แต่ละ subnet ใน VPC ต้องผูกกับ route table หนึ่งตัว ซึ่งควบคุมการกำหนดเส้นทางของ subnet นั้น subnet หนึ่งผูกกับ route table ได้ครั้งละหนึ่งตัวเท่านั้น แต่หลาย subnets ผูกกับ route table เดียวกันได้
ในการใช้ internet gateway, route table ของ subnet ต้องมี route ที่ส่งทราฟฟิกที่มุ่งสู่อินเทอร์เน็ตไปยัง internet gateway หาก subnet ผูกกับ route table ที่มี route ไปยัง internet gateway จะเรียกว่า public subnet
ในงานนี้ คุณจะ:
- สร้าง public route table สำหรับทราฟฟิกที่มุ่งสู่อินเทอร์เน็ต
- เพิ่ม route ใน route table เพื่อส่งทราฟฟิกที่มุ่งสู่อินเทอร์เน็ตไปยัง internet gateway
- ผูก public subnet เข้ากับ route table ใหม่
- 18. ในแถบนำทางด้านซ้าย เลือก **Route Tables**
  - จะมีหลาย route tables แสดงอยู่ แต่มีเพียงตัวเดียวที่ผูกกับ Lab VPC route table นี้ส่งทราฟฟิกภายใน (locally) จึงเรียกว่า Private Route Table
