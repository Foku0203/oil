# โมดูล 2: Lab 1 – การใช้ AWS Systems Manager
AWS Systems Manager คือชุดความสามารถสำหรับตั้งค่าและจัดการ Amazon EC2 instances, เซิร์ฟเวอร์และเครื่องเสมือนแบบ on-premises และทรัพยากร AWS อื่น ๆ ในระดับใหญ่ Systems Manager มีอินเทอร์เฟซรวมที่ช่วยให้คุณรวมศูนย์ข้อมูลการปฏิบัติงานและทำงานต่าง ๆ บนทรัพยากร AWS ให้เป็นอัตโนมัติได้ง่าย
ในแล็บนี้ คุณจะ:
- ใช้ AWS Systems Manager Inventory เพื่อตรวจสอบการตั้งค่าและสิทธิ์
- ใช้ AWS Systems Manager Run Command เพื่อรันงานบนเซิร์ฟเวอร์หลายเครื่อง
- ใช้ AWS Systems Manager Parameter Store เพื่ออัปเดตการตั้งค่าหรือ configuration ของแอปพลิเคชัน
- ใช้ AWS Systems Manager Session Manager เพื่อเข้าถึงบรรทัดคำสั่งบน instance
### ระยะเวลา (Duration)
แล็บนี้ใช้เวลาประมาณ **30 นาที**

## งานที่ 1: สร้างรายการ Inventory ของ Managed Instances
คุณสามารถใช้ AWS Systems Manager Inventory รวบรวม metadata ของระบบปฏิบัติการ แอปพลิเคชัน และ instance จาก Amazon EC2 instances และเซิร์ฟเวอร์หรือเครื่องเสมือน on-premises ในสภาพแวดล้อมแบบไฮบริดของคุณ คุณสามารถ query metadata เพื่อรู้อย่างรวดเร็วว่า instances ใดกำลังรันซอฟต์แวร์และการตั้งค่าที่นโยบายซอฟต์แวร์ของคุณกำหนด และ instances ใดต้องอัปเดต
ในงานนี้ คุณจะใช้ AWS Systems Manager Inventory รวบรวมข้อมูล inventory จาก Amazon EC2 instance
- 5. ใน AWS Management Console ที่เมนู **Services** คลิก **Systems Manager**
- 6. ในแถบนำทางด้านซ้าย คลิก **Fleet Manager**
- 7. ใต้ **Managed Instances** เลือก instance ชื่อ **Managed Instance**
- 8. จากเมนู **Account management** เลือก **Set up inventory** แล้วตั้งค่า:
  - ตอนนี้คุณจะสร้าง association ที่รวบรวมข้อมูลเกี่ยวกับซอฟต์แวร์และการตั้งค่าของ managed instance
  - **Name:** `Inventory-Association`
  - **Targets:** Manually selecting instances (เลือก instances เอง)
    - เลือก **Managed Instance**
- 9. คลิก **Setup Inventory** (ที่ด้านล่างของหน้า)
  - ตอนนี้ AWS Systems Manager Inventory จะเก็บ inventory ของ instance ตามคุณสมบัติที่เลือกเป็นประจำ
- 10. คลิกลิงก์ **Instance ID** ที่แสดงในแถว Managed Instance
- 11. คลิกแท็บ **Inventory**
รายการแอปพลิเคชันทั้งหมดบน instance จะแสดงขึ้นมา หากไม่มีอะไรปรากฏ ให้รอหนึ่งนาทีแล้วรีเฟรชหน้า
ใช้เวลาสักครู่ทบทวนแอปพลิเคชันที่ติดตั้งไว้และตัวเลือกอื่น ๆ ในเมนูดรอปดาวน์ **Inventory type**
คุณสร้าง inventory association ของ AWS Systems Manager ให้ instance สำเร็จแล้ว ด้วย AWS Systems Manager Inventory คุณสามารถทบทวนและตรวจสอบการตั้งค่าซอฟต์แวร์บน instances ได้โดยไม่ต้อง SSH เข้าแต่ละ instance

## งานที่ 3: ใช้ Parameter Store จัดการการตั้งค่าแอปพลิเคชัน
AWS Systems Manager Parameter Store ให้พื้นที่จัดเก็บแบบลำดับชั้นที่ปลอดภัยสำหรับการจัดการข้อมูลการตั้งค่าและการจัดการความลับ (secrets) คุณสามารถเก็บข้อมูล เช่น รหัสผ่าน สตริงเชื่อมต่อฐานข้อมูล และรหัสใบอนุญาต เป็นค่าพารามิเตอร์ได้ เก็บค่าเป็นข้อความธรรมดาหรือข้อมูลที่เข้ารหัสก็ได้ จากนั้นอ้างอิงค่าด้วยชื่อที่ไม่ซ้ำกันที่คุณกำหนดตอนสร้างพารามิเตอร์
ในงานนี้ คุณจะใช้ AWS Systems Manager Parameter Store เก็บพารามิเตอร์ที่จะใช้เปิดใช้งานคุณสมบัติหนึ่งในแอปพลิเคชัน
- 26. เปิดแท็บ Dashboard ค้างไว้ แต่กลับไปที่แท็บ Management Console

  - แอปพลิเคชันที่รันบน EC2 instance จะตรวจสอบโดยอัตโนมัติว่ามีพารามิเตอร์นี้หรือไม่ หากพบ จะแสดงคุณสมบัติเพิ่มเติม

## งานที่ 4: ใช้ Session Manager เข้าถึง Instances
AWS Systems Manager Session Manager ช่วยให้คุณจัดการ Amazon EC2 instances ผ่าน shell บนเบราว์เซอร์แบบโต้ตอบที่คลิกเดียว หรือผ่าน AWS CLI Session Manager ให้การจัดการ instance ที่ปลอดภัยและตรวจสอบได้ โดยไม่ต้องเปิด inbound ports ไม่ต้องดูแล bastion hosts และไม่ต้องจัดการ SSH keys Session Manager ยังทำให้ปฏิบัติตามนโยบายองค์กรได้ง่าย ซึ่งนโยบายกำหนดให้ควบคุมการเข้าถึง instances มีแนวปฏิบัติด้านความปลอดภัยที่เข้มงวด และมี log ที่ตรวจสอบได้ครบถ้วนพร้อมรายละเอียดการเข้าถึง instance ในขณะที่ยังให้ผู้ใช้ปลายทางเข้าถึง Amazon EC2 instances ข้ามแพลตฟอร์มได้ง่ายด้วยการคลิกเดียว

- 36. รันคำสั่งนี้ในหน้าต่าง session:
```
ls /var/www/html
```
- คุณจะเห็นไฟล์ของแอปพลิเคชันที่ติดตั้งบน instance
- 37. รันคำสั่งนี้ในหน้าต่าง session:
```
# Get region
AZ=`curl -s http://169.254.169.254/latest/meta-data/placement/availability-zone`
export AWS_DEFAULT_REGION=${AZ::-1}

# List information about EC2 instances
aws ec2 describe-instances
```
(คอมเมนต์ในคำสั่ง: ดึงชื่อ region / แสดงข้อมูลของ EC2 instances)
> หมายเหตุผู้แปล: ในต้นฉบับ PDF บรรทัด `AZ=...` ถูกตัดท้ายเหลือ `.../meta-data/placem` จึงเติมให้ครบเป็น `placement/availability-zone` ตามคำสั่งมาตรฐานของ AWS
- สิ่งนี้แสดงให้เห็นว่า AWS Systems Manager Session Manager ใช้ล็อกอินเข้า instance ได้โดยไม่ต้องใช้ SSH ที่จริงแล้ว instance นี้ไม่ได้เปิดพอร์ต SSH 22 ไว้ใน Security Group
> **ไม่บังคับ (Optional):** คุณสามารถตรวจสอบได้โดยเปิดดู Security Group ที่ instance ใช้
การเข้าถึง Session Manager สามารถจำกัดได้ด้วย IAM policies และการใช้งานจะถูกบันทึกใน AWS CloudTrail ซึ่งให้ความปลอดภัยและการตรวจสอบที่ดีกว่าการเข้าถึงผ่าน SSH แบบดั้งเดิมมาก
