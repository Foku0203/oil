# โมดูล 10: Lab 7 – การจัดการทรัพยากรด้วย Tagging (Managing Resources with Tagging)
(ต้นฉบับ .md มีคำว่า "choosing" หลงอยู่บรรทัดแรกก่อนหัวข้อ ซึ่งไม่ใช่เนื้อหา)
แล็บนี้แบ่งเป็นสองส่วน:
- ในส่วน**งาน (Task)** ของแล็บ คุณจะใช้ AWS Command Line Interface (CLI) ตรวจดู tags ที่กำหนดให้ Amazon EC2 instances จำนวนหนึ่ง จากนั้นใช้สคริปต์ที่เตรียมไว้ให้ ปิดและเปิด Amazon EC2 instances หลายตัวพร้อมกันตาม tags
- ในส่วน**โจทย์ท้าทาย (Challenge)** คุณจะถูกท้าทายให้คิดวิธี terminate instances ที่ไม่ได้ติด tags ตามที่กำหนด
**วัตถุประสงค์ (Objectives)**
หลังจากทำแล็บนี้เสร็จ คุณจะสามารถ:
- ติด tags ให้ทรัพยากร AWS ที่มีอยู่
- ค้นหาทรัพยากรตาม tags
- ใช้ AWS CLI หรือ AWS SDK for PHP หยุดและ terminate Amazon EC2 instances ตามคุณลักษณะบางอย่างของทรัพยากร
**ระยะเวลา (Duration)**
แล็บนี้ใช้เวลาประมาณ **30 นาที**
**สถานการณ์ (Scenario)**
สภาพแวดล้อมของแล็บนี้ (ดังภาพด้านล่าง) ประกอบด้วย:
- Amazon VPC ชื่อ Lab VPC
- Public subnet
- Private subnet
- Amazon EC2 Linux instance ชื่อ CommandHost [เครื่องมือ AWS Command Line Interface (CLI) ถูกติดตั้งและตั้งค่าไว้ให้แล้วบน instance นี้]
- Amazon EC2 Linux instances 8 ตัว
- private instances มี tags แบบกำหนดเองสามตัว:

| ชื่อ Tag | เนื้อหา |

### ค้นหา Development Instances ของโปรเจกต์
เมื่อล็อกอินแล้ว คุณใช้ AWS CLI ค้นหาทรัพยากรใน private subnet ที่สังกัดโปรเจกต์ **ERPSystem** และอยู่ใน Environment ชื่อ **development** ได้ คุณจะได้เห็นวิธีใช้ตัวเลือก **--query** ของ AWS CLI สร้างผลลัพธ์ที่จัดรูปแบบอย่างดีด้วย
- 26. เพื่อค้นหา instances ทั้งหมดในบัญชีที่ติด tag **Project** ด้วยค่า **ERPSystem** ให้คัดลอกคำสั่งต่อไปนี้แล้วรันในหน้าต่าง Linux terminal:
```
aws ec2 describe-instances --filter "Name=tag:Project,Values=ERPSystem"
```
  - คำสั่งควรแสดงชุดพารามิเตอร์ทั้งหมดของ instances ทั้งเจ็ดตัวที่ติด tag **Project=ERPSystem** ผลลัพธ์มีจำนวนมาก และส่วนใหญ่ไม่เกี่ยวกับแล็บนี้ ในขั้นถัดไป คุณจะใช้พารามิเตอร์ **--query** จำกัดผลลัพธ์ให้แคบลง
- 27. ใช้พารามิเตอร์ `--query` จำกัดผลลัพธ์ของคำสั่งก่อนหน้าให้เหลือเฉพาะ instance ID ของ instance ที่พบ:
```
aws ec2 describe-instances --filter "Name=tag:Project,Values=ERPSystem" --query 'Reservations[*].Instances[*].InstanceId'
```
  - ผลลัพธ์จะเป็นรายการ instance IDs:
```
[
 [
  "i-135b491e"
 ],
 [
  "i-3e584a33"
 ],
 …
]
```
  - คำสั่ง **--query** ในตัวอย่างนี้ใช้ไวยากรณ์ wildcard ของ JMESPath ระบุว่าคำสั่งควรวนผ่านทุก reservations และทุก instances แล้วส่ง InstanceId ของแต่ละ instance ในผลลัพธ์กลับมา
  - ดีกว่าการส่งคุณสมบัติทุกตัวของ instances กลับมา แต่ถ้าคุณต้องการหลายฟิลด์ในผลลัพธ์ล่ะ?
- 28. คัดลอกคำสั่งต่อไปนี้แล้วรันในหน้าต่าง Linux terminal เพื่อให้ผลลัพธ์มีทั้ง instance ID และ Availability Zone ของแต่ละ instance:
```
aws ec2 describe-instances --filter "Name=tag:Project,Values=ERPSystem" --query 'Reservations[*].Instances[*].{ID:InstanceId,AZ:Placement.AvailabilityZone}'
```
  - แต่ละผลลัพธ์จะส่งคู่ชื่อ/ค่ากลับมาสองคู่
  - คำสั่งนี้ต่อยอดการใช้ไวยากรณ์ JMESPath ของคำสั่งก่อนหน้า โดยใช้วงเล็บปีกการะบุ query หลายคุณสมบัติของแต่ละ instance ที่ส่งกลับมา: `object.{Alias1:PropertyName1,Alias2:PropertyName2,[…]}`
  - ดังที่เห็น คุณระบุชื่อแทน (alias) ของแต่ละคุณสมบัติได้ เพื่อให้ผลลัพธ์กระชับขึ้น
  - จากผลลัพธ์นี้ คุณเห็นชัดว่าตัวกรองทำงาน และเห็นเฉพาะ instances ที่สังกัดโปรเจกต์ **ERPSystem** อย่างไรก็ตาม คุณอาจยังระบุไม่ได้ว่า instances ใดถูกส่งกลับมาจากข้อมูลนี้ ในขั้นถัดไป คุณจะเห็นวิธีใส่ค่าของ tags แบบกำหนดเองในผลลัพธ์
- 29. เพื่อใส่ค่าของ tag **Project** ในผลลัพธ์ ให้คัดลอกและรันคำสั่งต่อไปนี้ใน Linux terminal:
```
aws ec2 describe-instances --filter "Name=tag:Project,Values=ERPSystem" --query 'Reservations[*].Instances[*].{ID:InstanceId,AZ:Placement.AvailabilityZone,Project:Tags[?Key==`Project`] | [0].Value}'
```
  - ตอนนี้ผลลัพธ์มีค่าของ tag Project:
```
[[{
   "Project": "ERPSystem",
   "AZ": "us-west-2a",
   "ID": "i-3250b838"
}],...]
```
  - ค่าของ tag ที่ระบุชื่อดึงได้ผ่าน JMESPath query โดยใช้ไวยากรณ์ต่อไปนี้:
```
Tags[?Key==\`Project\`] | [0].Value
```
  - ไวยากรณ์นี้สั่งให้ JMESPath หาทุกองค์ประกอบในอาร์เรย์ **Tags** ที่มีค่า **Key** เป็น **Project** ผลลัพธ์ของคำสั่งนั้น (ซึ่งจะเป็นองค์ประกอบ Tags ตัวเดียว) ถูกส่งต่อ (pipe) ไปยังอีกคำสั่งหนึ่งที่เลือกองค์ประกอบแรกของชุดที่กรองแล้ว และเลือกพารามิเตอร์ชื่อ **Value** ซึ่งคือค่าของ tag **Project** จากนั้นผลลัพธ์นี้ถูกกำหนดชื่อแทนว่า **Project**
- 30. คัดลอกและรันคำสั่งต่อไปนี้เพื่อใส่ tags Environment และ Version ในผลลัพธ์ด้วย:
```
aws ec2 describe-instances --filter "Name=tag:Project,Values=ERPSystem" --query 'Reservations[*].Instances[*].{ID:InstanceId,AZ:Placement.AvailabilityZone,Project:Tags[?Key==`Project`] | [0].Value,Environment:Tags[?Key==`Environment`] | [0].Value,Version:Tags[?Key==`Version`] | [0].Value}'
```
  - ผลลัพธ์จะให้ภาพที่ครบถ้วนขึ้นของ instances ที่สังกัดโปรเจกต์ชื่อ **ERPSystem** ในปัจจุบัน:
```
[[{
 "Environment": "production",
 "Project": "ERPSystem",
 "Version": "1.0",
 "AZ": "us-west-2a",
 "ID": "i-3250b838"
 }],
  …
]
```
- 31. สุดท้าย เพิ่มตัวกรอง tag ตัวที่สองเพื่อดูเฉพาะ instances ที่สังกัดโปรเจกต์ **ERPSystem** และอยู่ใน Environment ชื่อ **development**:
```
aws ec2 describe-instances --filter "Name=tag:Project,Values=ERPSystem" "Name=tag:Environment,Values=development" --query 'Reservations[*].Instances[*].{ID:InstanceId,AZ:Placement.AvailabilityZone,Project:Tags[?Key==`Project`] | [0].Value,Environment:Tags[?Key==`Environment`] | [0].Value,Version:Tags[?Key==`Version`] | [0].Value}'
```
  - คำสั่งนี้ควรส่ง instances กลับมาเพียงสองตัว ทั้งคู่มีค่า tag **Project** เป็น ERPSystem และค่า tag **Environment** เป็น development:
```
[[{
 "Environment": "development",
 "Project": "ERPSystem",
 "Version": "1.0",
 "AZ": "us-west-2a",
 "ID": "i-9552ba9f"
 }],
   ...
]
```
### เปลี่ยน Version Tag สำหรับกระบวนการ Development
ในขั้นตอนนี้ คุณจะเปลี่ยน tags **Version** ทั้งหมดบน instances ที่ระบุเป็น **development** ของโปรเจกต์ **ERPSystem**
คุณอาจตั้งค่าคุณสมบัติเหล่านี้ทีละ instance ได้ แต่วิธีอัตโนมัติใช้งานได้จริงมากกว่า คุณใช้ Linux Bash shell script ง่าย ๆ ต่อยอดจาก query ที่สร้างไว้ก่อนหน้า และแก้ไขรายการ tags เป็นชุด (batch) ได้
- 32. บน CommandHost เปิดไฟล์ **/home/ec2-user/change-resource-tags.sh**:
```
nano change-resource-tags.sh
```
- 33. ตรวจดูเนื้อหาของสคริปต์:
```
#!/bin/bash
ids=$(aws ec2 describe-instances --filter "Name=tag:Project,Values=ERPSystem" "Name=tag:Environment,Values=development" --query 'Reservations[*].Instances[*].InstanceId' --output text)
aws ec2 create-tags --resources $ids --tags 'Key=Version,Value=1.1'
```
  - สคริปต์นี้ใช้คำสั่ง `aws ec2 describe-instances` ก่อน เพื่อส่งรายการ instance IDs ของเครื่อง development ที่สังกัดโปรเจกต์ **ERPSystem** เท่านั้น จากนั้นส่งค่าเหล่านั้นให้คำสั่ง `aws ec2 create-tags` ซึ่งจะสร้าง tag ใหม่หรือ (ในกรณีนี้) เขียนทับ tag ที่มีอยู่
  - สังเกตว่าคำสั่งแรกใช้ตัวเลือก **--output text** เพื่อจัดการผลลัพธ์เป็นข้อความแทน JSON การใช้แบบนี้แทน JSON กับผลลัพธ์ง่าย ๆ (ในกรณีนี้คือรายการ IDs) ทำให้จัดการผลลัพธ์และส่งต่อให้คำสั่งอื่นได้ง่ายขึ้น
- 34. ปิดโปรแกรมแก้ไข nano แล้วรันคำสั่งนี้จาก Linux command prompt:
```
./change-resource-tags.sh
```
- 35. เพื่อตรวจสอบว่าหมายเลขเวอร์ชันบน instances เหล่านี้เพิ่มขึ้นแล้ว และ instances อื่นที่ไม่ใช่ development ในโปรเจกต์ **ERPSystem** ไม่ได้รับผลกระทบ ให้คัดลอกและรันคำสั่งต่อไปนี้:
```
aws ec2 describe-instances --filter "Name=tag:Project,Values=ERPSystem" --query 'Reservations[*].Instances[*].{ID:InstanceId, AZ:Placement.AvailabilityZone, Project:Tags[?Key==`Project`] |[0].Value,Environment:Tags[?Key==`Environment`] | [0].Value,Version:Tags[?Key==`Version`] | [0].Value}'
```

## งานที่ 3: โจทย์ท้าทาย: terminate Instances ที่ไม่ปฏิบัติตามข้อกำหนด
ในโจทย์นี้ คุณจะถูกขอให้หาวิธี terminate instances ที่ไม่เป็นไปตามแนวทางความปลอดภัยบางอย่าง
> **หมายเหตุ:** หากคุณคุ้นเคยกับ AWS อยู่แล้ว เราแนะนำให้ลองทำโจทย์นี้ด้วยตัวเอง**ก่อน**อ่านเฉลยละเอียดในส่วนถัดไป เมื่อทำเสร็จแล้วให้ตรวจงานด้วยการทบทวนเฉลยละเอียด
**คำอธิบายโจทย์ (Challenge Description)**
**สถานการณ์:** บริษัทต้องการให้คุณสร้างกระบวนการอัตโนมัติที่จะ terminate instances ที่อาจเปิดช่องให้เกิดการละเมิดความปลอดภัยโดยอัตโนมัติ คุณได้ระบุรายการความเสี่ยงด้านความปลอดภัยแล้ว และกำลังตัดสินใจว่าจะทำอย่างมีประสิทธิภาพด้วยคำสั่ง AWS CLI หรือ PHP SDK for AWS
**โจทย์:** งานด้านความปลอดภัยงานแรกของคุณง่าย: ค้นหา instances ทั้งหมดใน private subnet ที่ไม่ได้ติด tag **Environment** แล้ว terminate (หรือนโยบาย "tag-or-terminate" – ติด tag หรือถูก terminate)
**คำใบ้ (Hints):**
- หากคุณไม่ถนัด PHP หรือภาษาโปรแกรมที่คล้ายกัน (เช่น Python หรือ Ruby) ที่มี AWS SDK ให้ใช้ ให้ลองใช้ชุดคำสั่ง AWS CLI ทำงานนี้
- การเรียก AWS PHP `Ec2::terminateInstances()` terminate instances ได้ คำสั่ง AWS CLI ที่เทียบเท่าคือ `aws ec2 terminate-instances`
- คุณใช้สคริปต์ **stopinator** จากส่วนที่ 2 เป็นแนวทางในการเขียนโค้ดได้
**ภาพรวมเฉลย (Challenge Solution Overview)**
มีหลายวิธีในการแก้โจทย์นี้ ด้วยโซลูชันแบบเขียนโปรแกรมหรือบรรทัดคำสั่งที่หลากหลาย วิธีแก้ทั่วไปประกอบด้วยขั้นตอนต่อไปนี้:
- ระบุ instances ทั้งหมดที่มี tag **Environment** อยู่ในขณะนี้
- เทียบกับรายการ instances ทั้งหมดที่มีอยู่ และบันทึก instance IDs ของ instances ที่ไม่อยู่ในรายการที่ได้จากงานที่ 1
- ส่ง instance IDs ของ instances ที่ไม่ได้ติด tag ให้ AWS โดยใช้คำสั่ง aws ec2 stop-instance (AWS CLI – ตามต้นฉบับ) หรือการเรียก API **Ec2::terminateInstances()** (PHP)
เฉลยต่อไปนี้แสดงวิธีแก้โจทย์นี้ด้วยสคริปต์ PHP
